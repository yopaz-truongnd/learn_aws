## 1. Kiến thức trọng tâm (Exam Notes)

### 1.1. Quy trình 7 bước khởi tạo Auto Scaling Group (`Demo ASG`)
1. **Bước chuẩn bị:** Terminate toàn bộ các EC2 instances tạo thủ công trước đó để quan sát ASG tự động tạo máy từ con số 0.
2. **Bước 1 — Tạo Launch Template (`my-demo-template`):**
   - Chọn **AMI:** Amazon Linux 2 (`x86`, Free tier eligible).
   - Chọn **Instance type:** `t2.micro`.
   - Chọn **Key pair:** `EC2 Tutorial`.
   - **Network settings:** **Không chọn Subnet** trong Launch Template (Subnets sẽ được chọn ở cấp độ ASG). Chọn **Security Group:** `launch-wizard-1` (cho phép HTTP từ ALB Security Group).
   - **Storage:** 8 GB `gp2`.
   - **Advanced details -> User data:** Dán script khởi tạo Apache Web Server (`Hello World`).
3. **Bước 2 — Chọn Network & AZ Distribution trên ASG:**
   - Chọn **VPC** và chọn tất cả **3 Subnets (3 Availability Zones)**.
   - **Availability Zone distribution:** `Balanced best effort` (cố gắng phân bổ số lượng EC2 instances đồng đều nhất giữa các AZ).
4. **Bước 3 — Tích hợp Load Balancer & Health Checks:**
   - Chọn **Attach to an existing load balancer** -> Chọn Target Group `demo-tg-alb`.
   - **Health checks:** Bật thêm **Turn on Elastic Load Balancing health checks** (bên cạnh EC2 health checks mặc định) để nếu ứng dụng web trên EC2 bị lỗi HTTP, ASG cũng biết và tự động thay thế instance.
5. **Bước 4 — Cấu hình Group Size:**
   - Ban đầu đặt `Desired capacity = 1`, `Min capacity = 1`, `Max capacity = 1`.
6. **Bước 5 — Quan sát Activity History & Instance Management:**
   - ASG thấy hiện tại có `0` instance trong khi `Desired = 1` -> Tự động khởi chạy 1 EC2 instance mới, tự động đăng ký vào `demo-tg-alb`.
7. **Bước 6 — Thử nghiệm Scale Out và Scale In thủ công:**
   - Sửa `Desired capacity = 2`, `Max capacity = 2` -> ASG tự động tạo thêm EC2 instance thứ 2 và gắn vào ALB.
   - Giảm `Desired capacity = 1` -> ASG tự động chọn 1 trong 2 EC2 instances, hủy đăng ký khỏi Target Group và **Terminate** instance đó.
