4. Cơ chế mạng nâng cao (Enhanced Networking) & Hệ thống AWS Nitro 4. Enhanced Networking & AWS Nitro System
Tối ưu hiệu năng truyền tải mạng và kiến trúc phần cứng thế hệ mới High-performance network virtualization and next-gen hardware architecture
Enhanced Networking: ENA vs EFA
Elastic Network Adapter (ENA) Bộ điều hợp mạng ảo hóa SR-IOV đem lại băng thông lên tới 100 Gbps, gói tin mỗi giây (PPS) cao và độ trễ cực thấp. Tiêu chuẩn mặc định cho hầu hết máy chủ EC2 hiện đại. SR-IOV virtualized network adapter supporting up to 100 Gbps, high PPS, and low jitter. Baseline standard for modern EC2 instances.
Elastic Fabric Adapter (EFA) — Bẫy thi HPC! Thiết bị mạng chuyên dụng cho tính toán hiệu năng cao (HPC), Machine Learning và mô phỏng tài chính. Sử dụng giao thức Message Passing Interface (MPI), cho phép bỏ qua tầng nhân hệ điều hành (OS Kernel Bypass) để giao tiếp liên node với độ trễ thấp nhất có thể. Dedicated network device for High Performance Computing (HPC) and distributed ML. Uses MPI protocol with OS Kernel Bypass for ultra-low inter-node latency.
Hệ thống AWS Nitro System
Phần cứng chuyên dụng độc lập AWS chuyển toàn bộ các tác vụ ảo hóa (Mạng VPC, Lưu trữ EBS, Bảo mật) sang các thẻ phần cứng rời chuyên biệt (Nitro Cards), giải phóng 100% tài nguyên CPU/RAM của máy chủ vật lý cho máy ảo EC2 của khách hàng. Offloads virtualization functions (VPC networking, EBS storage, security) to dedicated PCIe Nitro Cards, freeing 100% host CPU/RAM for guest EC2 workloads.
Bảo mật tuyệt đối (Nitro Enclaves) Môi trường tính toán cách ly hoàn toàn, không có kết nối mạng ra ngoài, không có quyền truy cập root hay lưu trữ cục bộ, dùng để xử lý dữ liệu cực kỳ nhạy cảm (khóa mã hóa KMS, PII, thông tin thẻ tín dụng). Isolated compute environments with zero external network connectivity, no root access, and no persistent storage for processing ultra-sensitive data (KMS keys, PII).
Quản trị an toàn: SSM Session Manager
Không mở Port 22 / RDP Quản trị viên kết nối trực tiếp vào console shell từ trình duyệt hoặc CLI mà KHÔNG CẦN Public IP, không cần mở port 22, không cần Bastion Host. Connect securely to instance shells from browser or CLI with NO Public IP, NO open port 22, NO Bastion Host needed.
Ghi vết Audit toàn diện Mọi câu lệnh người dùng gõ vào shell đều được tự động mã hóa và ghi log lưu trữ vào Amazon S3 và CloudWatch Logs, dễ dàng kiểm toán tuân thủ. All executed commands are automatically recorded and audited to Amazon S3 and CloudWatch Logs for security compliance.

5. EC2 Placement Groups (Nhóm phân bổ phần cứng) 5. EC2 Placement Groups
Kiểm soát vị trí vật lý của các instances trên rack máy chủ AWS — Câu hỏi kinh điển trong đề thi Control physical instance placement across underlying server racks — Classic exam question
Cluster Placement Group
Gom tất cả instances vào cùng 1 rack vật lý trong 1 Availability Zone duy nhất. Đem lại độ trễ mạng cực thấp (< 1ms) và băng thông tối đa (10Gbps - 100Gbps).
Rủi ro: Sập rack phần cứng = tất cả cùng chết. Không thể trải dài qua nhiều AZs! Dành cho Big Data HPC, MPI.
Packs instances on the same hardware rack inside a single AZ. Ultra-low latency (< 1ms) and 10–100Gbps network.
Risk: Entire group fails if rack crashes. Cannot span multiple AZs! Ideal for Big Data HPC and MPI.
Spread Placement Group
Phân tán tuyệt đối từng instance ra các rack phần cứng vật lý hoàn toàn khác nhau (giới hạn tối đa 7 instances trên mỗi AZ). Tối đa hóa khả năng cách ly lỗi phần cứng. Dành cho các máy chủ tối quan trọng (Critical DB, Primary/Standby).
Strictly isolates each instance on separate hardware racks (strict max 7 instances per AZ per group). Maximizes hardware fault tolerance. Ideal for critical database primary/standby pairs.
Partition Placement Group
Chia AZ thành nhiều partitions độc lập (tối đa 7 partitions/AZ, mỗi partition chứa hàng trăm instance). Các partition không dùng chung rack vật lý. Khi 1 partition lỗi, các partition khác vẫn an toàn. Dành riêng cho Hadoop, HDFS, Cassandra, Kafka clusters.
Divides an AZ into logical partitions (up to 7 partitions/AZ, hundreds of instances per partition). Partitions never share racks. Designed for Hadoop, HDFS, Cassandra, and Kafka clusters.
Quy tắc vàng trong phòng thi Golden Exam Rules
Không thể gộp hoặc di chuyển một instance đang chạy vào Placement Group trừ khi dùng CLI/Console: Stop instance → Đổi Placement Group → Start instance.
Cannot move a running instance into a Placement Group without stopping: Stop instance → Modify Placement Group → Start instance.

Cơ chế EC2 Hibernation (Ngủ đông) EC2 Hibernation Mechanism
Khi Hibernate: Trạng thái RAM được lưu trực tiếp vào Root EBS Volume (bắt buộc phải được mã hóa bằng KMS). Khi bật lại, server không cần cold-boot mà phục hồi nguyên vẹn bộ nhớ cache và tiến trình đang chạy. Dung lượng RAM phải < 150GB.
When Hibernated: RAM contents are dumped into the Root EBS volume (must be encrypted with KMS). Upon restart, instance bypasses cold boot and restores exact memory cache and running processes. RAM must be < 150GB.
Spot Fleet Allocation Strategies Spot Fleet Allocation Strategies
• lowestPrice: Chọn pool giá rẻ nhất (nguy cơ bị thu hồi cao).
• diversified: Phân bổ đều qua nhiều pools khác nhau (tính sẵn sàng cao nhất).

• lowestPrice: Chooses cheapest pool (highest interruption risk).
• diversified: Distributes across multiple pools (highest availability).
• capacityOptimized: Chooses pool with optimal spare capacity (lowest interruption - Best Practice).
• priceCapacityOptimized: Optimal balance of price and capacity.
IMDSv1 vs IMDSv2 (Chống lỗ hổng SSRF)
IMDSv1 cho phép gọi GET trực tiếp tới http://169.254.169.254/latest/meta-data/, rất dễ bị tin tặc lợi dụng lỗi SSRF trên web để trích xuất IAM temporary credentials.
👉 Bắt buộc: Bật IMDSv2 (yêu cầu header HTTP PUT để lấy Session Token thời hạn ngắn trước khi gọi GET metadata).
IMDSv1 allows direct HTTP GET to http://169.254.169.254/latest/meta-data/, leaving systems vulnerable to SSRF credential theft.
👉 Mandatory: Enforce IMDSv2 (requires HTTP PUT header to fetch a short-lived Session Token prior to metadata retrieval).
Cờ "Delete on Termination" "Delete on Termination" Flag
Mặc định khi tạo instance, Root EBS Volume được bật DeleteOnTermination = true (sẽ bị xóa khi xóa instance). Các ổ đĩa EBS phụ gắn thêm (Attached Volumes) mặc định là false (vẫn tồn tại sau khi terminate instance).
By default at launch, the Root EBS Volume has DeleteOnTermination = true (deleted when instance is terminated). Additional attached EBS volumes default to false (preserved after termination).

7. Nguyên tắc vàng — SAA-C03 7. Golden Rules — SAA-C03
Ghi nhớ 4 nguyên tắc cốt lõi về EC2 Compute 4 essential compute principles to memorize
  • 1
    Tuyệt đối không lưu Access Keys trên EC2 Never Store Access Keys on EC2 Instances Luôn gắn IAM Role (Instance Profile) cho EC2 để máy chủ tự động nhận credentials ngắn hạn từ STS, không bao giờ nhúng AWS_ACCESS_KEY_ID vào source code hoặc disk. Always attach an IAM Role (Instance Profile) to EC2 so instances automatically receive short-term STS credentials. Never embed static AWS_ACCESS_KEY_ID on disk or in source code.
  • 2
    Bảo mật 3 tầng với Security Group Reference 3-Tier Defense with Security Group References Đặt Web/App server trong Private Subnet. Cấu hình Security Group của EC2 chỉ chấp nhận Inbound port 80/443 từ Security Group của ALB, chặn mọi truy cập trực tiếp từ Internet. Place backend servers in Private Subnets. Configure EC2 Security Groups to accept inbound traffic only from the ALB's Security Group ID, eliminating direct Internet exposure.
  • 3
    Quản trị an toàn bằng SSM Session Manager Secure Server Management via SSM Session Manager Ưu tiên SSM Session Manager để thay thế SSH/Bastion Host: không cần mở port 22, không cần Public IP và ghi vết audit toàn bộ lệnh người dùng vào S3/CloudWatch. Adopt SSM Session Manager over SSH/Bastion Hosts: zero open port 22, no Public IP requirements, and centralized audit logging of all executed commands into S3/CloudWatch.
  • !
    Bắt buộc nâng cấp lên IMDSv2 Mandate IMDSv2 for Security Compliance Luôn cấu hình HttpTokens=required (IMDSv2) cho EC2 instance trong bài toán bảo mật ngân hàng/doanh nghiệp để triệt tiêu nguy cơ trích xuất IAM credentials qua lỗ hổng SSRF. Enforce HttpTokens=required (IMDSv2) on all EC2 instances to neutralize SSRF vulnerabilities attempting to extract IAM STS credentials.
