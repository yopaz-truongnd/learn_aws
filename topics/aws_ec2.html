💡 Amazon EC2 (Elastic Compute Cloud) là dịch vụ gì? 💡 What is Amazon EC2 (Elastic Compute Cloud)? Amazon EC2 là dịch vụ Hạ tầng dưới dạng Dịch vụ (Infrastructure as a Service — IaaS) cho phép bạn thuê các máy chủ ảo (gọi là EC2 Instances) trên đám mây AWS chỉ trong vài chục giây và trả tiền theo thời gian sử dụng thực tế. Mỗi EC2 Instance nằm cố định trong 1 Availability Zone (AZ-Scoped). Theo mô hình trách nhiệm chung (Shared Responsibility Model), AWS chịu trách nhiệm vận hành phần cứng vật lý và tầng ảo hóa AWS Nitro Hypervisor, còn bạn có toàn quyền cấu hình Hệ điều hành (OS), bản vá bảo mật, tường lửa Security Group và ứng dụng bên trong. Amazon EC2 is AWS's foundational Infrastructure as a Service (IaaS) offering that lets you rent virtual servers (EC2 Instances) on demand within seconds. Each EC2 instance is strictly bound to a single Availability Zone (AZ-Scoped). Under the Shared Responsibility Model, AWS manages the physical datacenter and AWS Nitro Hypervisor, while you control the Guest OS, patching, Security Group firewall rules, and application stack.
6 Thành phần cấu tạo nên một máy chủ EC2 hoàn chỉnh (6 Core Building Blocks) 6 Core Building Blocks of an Amazon EC2 Instance
1. AMI (Amazon Machine Image) — Khuôn mẫu Hệ điều hành
Bản sao đóng gói sẵn chứa Hệ điều hành (Amazon Linux 2023, Ubuntu, RedHat, Windows Server, macOS), cấu hình phân vùng ổ đĩa gốc (Root Volume Template) và các phần mềm cài sẵn để đúc ra máy chủ EC2.
A pre-packaged template containing the Operating System (Amazon Linux 2023, Ubuntu, Windows, macOS), root volume mapping, and pre-installed software used to launch instances.
2. Instance Type (vCPU & RAM) — Năng lực tính toán
Quy định cấu hình phần cứng của máy ảo: số lượng vi xử lý ảo (vCPU), dung lượng bộ nhớ RAM, băng thông card mạng và bộ tăng tốc phần cứng (GPU/FPGA) theo từng họ máy (t3, m6i, c7g, r6g...).
Defines the virtual hardware profile: number of vCPUs, RAM capacity, network bandwidth, and hardware accelerators (GPUs/FPGAs) grouped by instance families (t3, m6i, c7g, r6g...).
3. Storage (EBS, Instance Store, EFS) — Ổ đĩa lưu trữ
• Amazon EBS: Ổ đĩa khối gắn qua mạng (Network Block Storage), giữ nguyên dữ liệu khi Stop máy.
• EC2 Instance Store: Ổ NVMe SSD vật lý gắn trực tiếp trên host, IOPS cực cao nhưng mất sạch dữ liệu khi Stop.
• Amazon EFS: Hệ thống tệp mạng dùng chung cho nhiều máy EC2 (Multi-AZ).
• Amazon EBS: Persistent network-attached block storage that survives instance stops.
• EC2 Instance Store: Physically attached ephemeral NVMe SSD with ultra-high IOPS (data lost on Stop).
• Amazon EFS: Shared Multi-AZ network file system.
4. Networking & IP (VPC, Subnet, ENI, IP) — Kết nối mạng
Máy chủ đặt trong 1 Subnet (thuộc 1 AZ) thông qua card mạng ảo ENI (Elastic Network Interface). Luôn có Private IPv4 cố định suốt vòng đời, tùy chọn gắn Public IPv4 (đổi khi Stop/Start) hoặc Elastic IP (IP công khai tĩnh cố định).
Placed inside a specific VPC Subnet (1 AZ) via a virtual network card (ENI). Assigned a persistent Private IPv4, an optional dynamic Public IPv4 (changes on Stop/Start), or a static Elastic IP.
5. Security & Access (Security Group, Key Pair, SSM)
• Security Group: Tường lửa trạng thái (Stateful Firewall) chặn/mở từng cổng TCP/UDP (ví dụ Port 22 SSH, Port 80 HTTP, Port 3389 RDP).
• Key Pair / SSM Session Manager: Cặp khóa mật mã (.pem) hoặc trình quản lý phiên không cần mở cổng để đăng nhập vào máy chủ.
• Security Group: Instance-level stateful firewall controlling inbound/outbound ports (Port 22 SSH, Port 80 HTTP, Port 3389 RDP).
• Key Pair / SSM Session Manager: Cryptographic key pair (.pem) or portless browser terminal access.
6. Bootstrapping & Identity (User Data, IAM Role, IMDS)
• EC2 User Data: Script tự động chạy dưới quyền root ở lần khởi động đầu tiên để cài phần mềm.
• IAM Instance Profile (Role) & IMDS (169.254.169.254): Cấp quyền bảo mật tạm thời cho EC2 gọi các dịch vụ AWS khác và tra cứu siêu dữ liệu nội bộ.
• EC2 User Data: First-boot root script automating software installation.
• IAM Role & IMDS (169.254.169.254): Grants temporary STS credentials to call AWS APIs and exposes instance metadata.

Là gì & Dùng khi nàoWhat is it & When to use • Là gì: Dịch vụ máy chủ ảo (IaaS) cho phép toàn quyền kiểm soát OS và tùy chỉnh CPU, RAM, Storage, Networking.
• Dùng khi nào: Cần quyền quản trị cấp OS, chạy script tự động lần đầu qua EC2 User Data, hoặc tối ưu chi phí theo tải (On-Demand, Reserved/Savings Plans, Spot, Dedicated Hosts). • What is it: Virtual Machine IaaS offering full OS control and customizable CPU, RAM, Storage, and Networking.
• When to use: Require OS-level control, first-boot automation via EC2 User Data, or tailored billing models.
Khác gì dịch vụ gần giống & Điểm hay bị hỏiDifferences & Exam Hotspots • EC2 vs Lambda / Fargate: EC2 quản lý cấp VM chạy liên tục; Lambda là Serverless FaaS (tối đa 15 phút); Fargate là Serverless Container.
• Dedicated Hosts vs Dedicated Instances: Chỉ Dedicated Hosts mới nhìn thấy Physical Sockets/Cores để dùng cho BYOL (Bring Your Own License).
• Mặc định & Từ khóa: EC2 User Data chỉ chạy 1 lần ở lần Launch đầu tiên dưới quyền root. Mặc định 1 CPU Core = 2 Threads (2 vCPUs). • EC2 vs Lambda / Fargate: EC2 is VM-level IaaS; Lambda is Serverless FaaS (max 15m); Fargate is Serverless Container.
• Dedicated Hosts vs Instances: Only Dedicated Hosts expose physical sockets/cores for server-bound BYOL.
• Defaults & Keywords: EC2 User Data runs once at first launch as root. Default 1 CPU Core = 2 Threads (2 vCPUs).
🛡️ 2. Security Groups, EIP & ENI 🛡️ 2. Security Groups, EIP & ENI
Security Groups (4 tiêu chí)Security Groups (4-Point Summary) • Là gì: Tường lửa ảo cấp độ Instance/ENI lọc lưu lượng theo Port, Protocol và IP/SG nguồn.
• Dùng khi nào: Cô lập các tầng Web → App → DB bằng Security Group Referencing.
• Khác gì NACL: SG là Stateful, chỉ có Allow; NACL ở cấp Subnet, Stateless, có cả Allow & Deny.
• Điểm hay hỏi: Mặc định Inbound chặn hết, Outbound mở hết. Lỗi Connection Timeout = do Security Group chặn; lỗi Connection Refused = ứng dụng trong EC2 chưa chạy! • What is it: Instance/ENI-level virtual firewall filtering by Port, Protocol, and Source IP/SG.
• When to use: Isolate Web → App → DB tiers via SG Referencing.
• vs NACL: SG is Stateful, Allow-only; NACL is Subnet-level, Stateless, Allow & Deny.
• Hotspots: Default Inbound Deny All, Outbound Allow All. Connection Timeout = SG blocked; Connection Refused = app down!
Elastic IP (EIP) & ENI (4 tiêu chí)Elastic IP (EIP) & ENI (4-Point Summary) • Là gì: EIP là Public IPv4 tĩnh cấp Region; ENI là card mạng ảo trong VPC gắn chặt với 1 AZ.
• Dùng khi nào: Dùng EIP khi cần cố định Public IPv4 qua Stop/Start hoặc whitelist firewall; dùng ENI khi cần failover Private IP cố định hoặc license gắn theo MAC address.
• Điểm hay hỏi: Tối đa 5 EIPs / Region mặc định; EIP bị tính phí nếu gắn vào máy Stopped hoặc để trống. Card chính eth0 không tháo rời được. • What is it: EIP is a static regional Public IPv4; ENI is an AZ-bound virtual network card.
• When to use: EIP for fixed Public IPv4 across Stop/Start; ENI to failover a specific Private IP or MAC-bound license.
• Hotspots: Default limit 5 EIPs / Region; billed if unattached or on Stopped EC2. Primary eth0 cannot be detached.
📦 3. Placement Groups & EC2 Hibernate 📦 3. Placement Groups & EC2 Hibernate
EC2 Placement Groups (4 tiêu chí)EC2 Placement Groups (4-Point Summary) • Là gì: Kiểm soát cách AWS đặt vị trí vật lý của EC2 trên phần cứng Rack.
• Khác nhau & Dùng khi nào:
  1. Cluster: Cùng 1 Rack / 1 AZ → mạng 10 Gbps+, độ trễ cực thấp cho HPC.
  2. Spread: Mỗi máy nằm trên 1 Rack riêng → tối đa 7 instances / AZ cho các Critical instances.
  3. Partition: Tối đa 7 partitions / AZ (hàng trăm EC2) cho HDFS, HBase, Cassandra, Kafka. • What is it: Controls physical placement of EC2 across AWS hardware racks.
• Differences & Use Cases:
  1. Cluster: Same rack / 1 AZ → 10 Gbps+ low-latency network for HPC.
  2. Spread: Separate hardware per instance → max 7 instances / AZ for critical VMs.
  3. Partition: Up to 7 partitions / AZ (100s of VMs) for HDFS, HBase, Cassandra, Kafka.
EC2 Hibernate (4 tiêu chí)EC2 Hibernate (4-Point Summary) • Là gì: Bảo toàn trạng thái in-memory (RAM) bằng cách ghi RAM xuống ổ Root EBS Volume khi tắt máy.
• Dùng khi nào: Ứng dụng mất nhiều thời gian khởi tạo hoặc cần giữ nguyên cache lớn trong RAM.
• Điểm hay hỏi: Ổ Root EBS bắt buộc phải mã hóa (Encrypted), RAM < 150 GB, tối đa 60 ngày. • What is it: Preserves in-memory (RAM) state by dumping RAM to the Root EBS Volume on stop.
• When to use: Long-running boot initialization or pre-warmed memory caches.
• Hotspots: Root EBS MUST be Encrypted, RAM < 150 GB, max 60 days.

Enhanced Networking: ENA vs EFA
Elastic Network Adapter (ENA) Bộ điều hợp mạng ảo hóa SR-IOV đem lại băng thông lên tới 100 Gbps, gói tin mỗi giây (PPS) cao và độ trễ cực thấp. Tiêu chuẩn mặc định cho hầu hết máy chủ EC2 hiện đại. SR-IOV virtualized network adapter supporting up to 100 Gbps, high PPS, and low jitter. Baseline standard for modern EC2 instances.
Elastic Fabric Adapter (EFA) — Bẫy thi HPC! Thiết bị mạng chuyên dụng cho tính toán hiệu năng cao (HPC), Machine Learning và mô phỏng tài chính. Sử dụng giao thức Message Passing Interface (MPI), cho phép bỏ qua tầng nhân hệ điều hành (OS Kernel Bypass) để giao tiếp liên node với độ trễ thấp nhất có thể. Dedicated network device for High Performance Computing (HPC) and distributed ML. Uses MPI protocol with OS Kernel Bypass for ultra-low inter-node latency.
Hệ thống AWS Nitro System
Phần cứng chuyên dụng độc lập AWS chuyển toàn bộ các tác vụ ảo hóa (Mạng VPC, Lưu trữ EBS, Bảo mật) sang các thẻ phần cứng rời chuyên biệt (Nitro Cards), giải phóng 100% tài nguyên CPU/RAM của máy chủ vật lý cho máy ảo EC2 của khách hàng. Offloads virtualization functions (VPC networking, EBS storage, security) to dedicated PCIe Nitro Cards, freeing 100% host CPU/RAM for guest EC2 workloads.
Bảo mật tuyệt đối (Nitro Enclaves) Môi trường tính toán cách ly hoàn toàn, không có kết nối mạng ra ngoài, không có quyền truy cập root hay lưu trữ cục bộ, dùng để xử lý dữ liệu cực kỳ nhạy cảm (khóa mã hóa KMS, PII, thông tin thẻ tín dụng). Isolated compute environments with zero external network connectivity, no root access, and no persistent storage for processing ultra-sensitive data (KMS keys, PII).
Quản trị an toàn: SSM Session Manager
Không mở Port 22 / RDP Quản trị viên kết nối trực tiếp vào console shell từ trình duyệt hoặc CLI mà KHÔNG CẦN Public IP, không cần mở port 22, không cần Bastion Host. Connect securely to instance shells from browser or CLI with NO Public IP, NO open port 22, NO Bastion Host needed.
Ghi vết Audit toàn diện Mọi câu lệnh người dùng gõ vào shell đều được tự động mã hóa và ghi log lưu trữ vào Amazon S3 và CloudWatch Logs, dễ dàng kiểm toán tuân thủ. All executed commands are automatically recorded and audited to Amazon S3 and CloudWatch Logs for security compliance.

5. EC2 Placement Groups (Nhóm phân bổ phần cứng) 5. EC2 Placement Groups
Kiểm soát vị trí vật lý của các instances trên rack máy chủ AWS — Câu hỏi kinh điển trong đề thi Control physical instance placement across underlying server racks — Classic exam question
Cluster Placement Group
Gom tất cả instances vào cùng 1 rack vật lý trong 1 Availability Zone duy nhất. Đem lại độ trễ mạng cực thấp (< 1ms) và băng thông tối đa (10Gbps - 100Gbps).
Rủi ro: Sập rack phần cứng = tất cả cùng chết. Không thể trải dài qua nhiều AZs! Dành cho Big Data HPC, MPI.
Packs instances on the same hardware rack inside a single AZ. Ultra-low latency (< 1ms) and 10–100Gbps network.
Risk: Entire group fails if rack crashes. Cannot span multiple AZs! Ideal for Big Data HPC and MPI.
Spread Placement Group
Phân tán tuyệt đối từng instance ra các rack phần cứng vật lý hoàn toàn khác nhau (giới hạn tối đa 7 instances trên mỗi AZ). Tối đa hóa khả năng cách ly lỗi phần cứng. Dành cho các máy chủ tối quan trọng (Critical DB, Primary/Standby).
Strictly isolates each instance on separate hardware racks (strict max 7 instances per AZ per group). Maximizes hardware fault tolerance. Ideal for critical database primary/standby pairs.
Partition Placement Group
Chia AZ thành nhiều partitions độc lập (tối đa 7 partitions/AZ, mỗi partition chứa hàng trăm instance). Các partition không dùng chung rack vật lý. Khi 1 partition lỗi, các partition khác vẫn an toàn. Dành riêng cho Hadoop, HDFS, Cassandra, Kafka clusters.
Divides an AZ into logical partitions (up to 7 partitions/AZ, hundreds of instances per partition). Partitions never share racks. Designed for Hadoop, HDFS, Cassandra, and Kafka clusters.
Quy tắc vàng trong phòng thi Golden Exam Rules
Không thể gộp hoặc di chuyển một instance đang chạy vào Placement Group trừ khi dùng CLI/Console: Stop instance → Đổi Placement Group → Start instance.
Cannot move a running instance into a Placement Group without stopping: Stop instance → Modify Placement Group → Start instance.

Cơ chế EC2 Hibernation (Ngủ đông) EC2 Hibernation Mechanism
Khi Hibernate: Trạng thái RAM được lưu trực tiếp vào Root EBS Volume (bắt buộc phải được mã hóa bằng KMS). Khi bật lại, server không cần cold-boot mà phục hồi nguyên vẹn bộ nhớ cache và tiến trình đang chạy. Dung lượng RAM phải < 150GB.
When Hibernated: RAM contents are dumped into the Root EBS volume (must be encrypted with KMS). Upon restart, instance bypasses cold boot and restores exact memory cache and running processes. RAM must be < 150GB.
Spot Fleet Allocation Strategies Spot Fleet Allocation Strategies
• lowestPrice: Chọn pool giá rẻ nhất (nguy cơ bị thu hồi cao).
• diversified: Phân bổ đều qua nhiều pools khác nhau (tính sẵn sàng cao nhất).

• lowestPrice: Chooses cheapest pool (highest interruption risk).
• diversified: Distributes across multiple pools (highest availability).
• capacityOptimized: Chooses pool with optimal spare capacity (lowest interruption - Best Practice).
• priceCapacityOptimized: Optimal balance of price and capacity.
IMDSv1 vs IMDSv2 (Chống lỗ hổng SSRF)
IMDSv1 cho phép gọi GET trực tiếp tới http://169.254.169.254/latest/meta-data/, rất dễ bị tin tặc lợi dụng lỗi SSRF trên web để trích xuất IAM temporary credentials.
👉 Bắt buộc: Bật IMDSv2 (yêu cầu header HTTP PUT để lấy Session Token thời hạn ngắn trước khi gọi GET metadata).
IMDSv1 allows direct HTTP GET to http://169.254.169.254/latest/meta-data/, leaving systems vulnerable to SSRF credential theft.
👉 Mandatory: Enforce IMDSv2 (requires HTTP PUT header to fetch a short-lived Session Token prior to metadata retrieval).
Cờ "Delete on Termination" "Delete on Termination" Flag
Mặc định khi tạo instance, Root EBS Volume được bật DeleteOnTermination = true (sẽ bị xóa khi xóa instance). Các ổ đĩa EBS phụ gắn thêm (Attached Volumes) mặc định là false (vẫn tồn tại sau khi terminate instance).
By default at launch, the Root EBS Volume has DeleteOnTermination = true (deleted when instance is terminated). Additional attached EBS volumes default to false (preserved after termination).
Chẩn đoán lỗi SSH/HTTP: Connection Timeout vs Connection Refused Troubleshooting: Connection Timeout vs Connection Refused
• Connection Timeout (Hết thời gian chờ): Gói tin bị chặn ở tầng mạng — 100% do Security Group chưa mở port (Port 22/80) hoặc sai IP nguồn.
• Connection Refused (Từ chối kết nối): Đã đi qua được Security Group vào tới EC2, nhưng dịch vụ web (httpd/nginx) bên trong chưa chạy!
• EC2 Instance Connect: Đăng nhập SSH ngay trên trình duyệt mà không cần quản lý file .pem (AWS đẩy khóa SSH tạm thời lên máy nhưng vẫn cần mở Port 22).
• Connection Timeout: Packet dropped silently at firewall — caused by Security Group blocking port 22/80.
• Connection Refused: Passed Security Group, but application daemon (httpd/nginx) inside OS is not running!
• EC2 Instance Connect: Browser-based SSH using ephemeral keys pushed by AWS (still requires Port 22 open unless using Instance Connect Endpoint).
Tùy chỉnh CPU Options (vCPU & Threads per Core) Optimize CPU Options (vCPU & Threads per Core)
• Mặc định trên EC2: 1 Physical CPU Core = 2 Threads (2 vCPUs) nhờ công nghệ Hyper-Threading (Simultaneous Multithreading).
• Có thể tùy chỉnh chỉ lúc Launch Instance: Tắt multithreading (ThreadsPerCore = 1) cho bài toán HPC, hoặc giảm số lượng Active CPU Cores để tiết kiệm chi phí bản quyền phần mềm tính theo vCPU (BYOL).
• By default on EC2: 1 Physical CPU Core = 2 Threads (2 vCPUs) via Simultaneous Multithreading.
• Configurable only at instance launch: Disable multithreading (ThreadsPerCore = 1) for HPC workloads, or reduce active CPU core count to cut per-vCPU software licensing costs (BYOL).

    Tuyệt đối không lưu Access Keys trên EC2 Never Store Access Keys on EC2 Instances Luôn gắn IAM Role (Instance Profile) cho EC2 để máy chủ tự động nhận credentials ngắn hạn từ STS, không bao giờ nhúng AWS_ACCESS_KEY_ID vào source code hoặc disk.     Bảo mật 3 tầng với Security Group Reference 3-Tier Defense with Security Group References Đặt Web/App server trong Private Subnet. Configure EC2 Security Groups to accept inbound traffic only from the ALB's Security Group ID, eliminating direct Internet exposure.
  • 3
    Quản trị an toàn bằng SSM Session Manager Secure Server Management via SSM Session Manager Ưu tiên SSM Session Manager để thay thế SSH/Bastion Host: không cần mở port 22, không cần Public IP và ghi vết audit toàn bộ lệnh người dùng vào S3/CloudWatch. Adopt SSM Session Manager over SSH/Bastion Hosts: zero open port 22, no Public IP requirements, and centralized audit logging of all executed commands into S3/CloudWatch.
  • !
    Bắt buộc nâng cấp lên IMDSv2 Mandate IMDSv2 for Security Compliance Luôn cấu hình HttpTokens=required (IMDSv2) cho EC2 instance trong bài toán bảo mật ngân hàng/doanh nghiệp để triệt tiêu nguy cơ trích xuất IAM credentials qua lỗ hổng SSRF. Enforce HttpTokens=required (IMDSv2) on all EC2 instances to neutralize SSRF vulnerabilities attempting to extract IAM STS credentials.
