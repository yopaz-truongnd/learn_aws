1. Các họ Instance Types cốt lõi
Chọn đúng loại máy chủ theo đặc tính tải (Workload Characteristics)
General Purpose (t3, t4g, m5, m6i)
Cân bằng tối ưu giữa CPU, RAM và Networking. Phù hợp cho web server, backend API, môi trường phát triển (Dev/Test) và cơ sở dữ liệu nhỏ.
Cân bằngBurstable CPU (t-series)Web Servers
Compute Optimized (c5, c6g, c7g)
Tập trung vi xử lý CPU hiệu năng cao. Lý tưởng cho xử lý dữ liệu hàng loạt (Batch Processing), mã hóa media (Transcoding), máy chủ game chuyên dụng và mô hình Machine Learning inference.
High CPU/CoreBatch ProcessingMedia Encoding
Memory Optimized (r5, r6g, x1, z1d)
Dung lượng RAM cực lớn giúp xử lý khối dữ liệu khổng lồ trực tiếp trong bộ nhớ. Dùng cho In-memory Databases (Redis, Memcached), cơ sở dữ liệu quan hệ lớn và phân tích dữ liệu thời gian thực.
High RAMRedis / MemcachedReal-time Big Data
Storage Optimized (i3, i4i, d2, d3, h1)
Yêu cầu truy xuất đọc/ghi đĩa I/O cực cao với độ trễ thấp trên khối dữ liệu cục bộ. Sử dụng trực tiếp ổ NVMe SSD nội bộ cho Data Warehousing, Apache Cassandra, Hadoop distributed file systems.
High IOPSNVMe SSD cục bộData Warehousing

2. Các mô hình thanh toán (Purchasing Options)
Chiến lược tối ưu hóa chi phí (Cost Optimization) trong đề thi SAA-C03
Linh hoạt & Tạm thời
On-DemandTrả theo giây/giờ sử dụng thực tế. Không cần cam kết trước. Chi phí cao nhất nhưng linh hoạt nhất cho workload mới, không dự đoán trước được thời gian chạy.
Spot InstancesĐấu giá dung lượng máy chủ nhàn rỗi của AWS. Giảm giá tới 90% so với On-Demand. Có thể bị AWS thu hồi bất kỳ lúc nào với cảnh báo trước 2 phút. Dành cho Batch jobs, Stateless web app, Rendering video. Không dùng cho DB hoặc critical workloads!
Capacity ReservationsGiữ chỗ trước phần cứng trong một AZ cụ thể. Không cần cam kết 1-3 năm. Tính phí theo giá On-Demand dù có chạy instance hay không.
Cam kết dài hạn (1 hoặc 3 năm)
Reserved Instances (RI)Cam kết 1 hoặc 3 năm. Giảm tới 72%.
• Standard RI: Không đổi được họ instance.
• Convertible RI: Được đổi họ instance, OS, tenancy (giảm giá ít hơn).
• Hình thức: All Upfront, Partial Upfront, No Upfront.
Savings PlansCam kết chi tiêu theo mức tiền cố định mỗi giờ (ví dụ $10/h) trong 1 hoặc 3 năm. Linh hoạt vượt trội so với RI: tự động áp dụng khi chuyển đổi giữa các thế hệ máy chủ EC2, AWS Fargate và AWS Lambda!
Cách ly phần cứng (Hardware Isolation)
Dedicated HostsThuê nguyên một máy chủ vật lý riêng biệt của AWS. Kiểm soát trực tiếp số core/socket vật lý để tuân thủ giấy phép phần mềm theo core (BYOL: Bring Your Own License) và quy định pháp lý khắt khe.
Dedicated InstancesChạy trên phần cứng dành riêng cho một tài khoản khách hàng, nhưng AWS quản lý vị trí socket. Tính phí thêm theo mỗi giờ chạy instance.

4. User Data & Instance Metadata
Bootstrapping & IMDSv1 vs IMDSv2
EC2 User Data (Bootstrapping)
Đoạn bash script tự động chạy với quyền root ở lần khởi động đầu tiên duy nhất của instance. Dùng để cài web server, kéo source code, cấu hình môi trường.
Chạy 1 lần lúc tạoRoot privileges
Instance Metadata Service (IMDS)
Lấy thông tin nội bộ của máy chủ tại IP nội bộ http://169.254.169.254/latest/meta-data/ (IP nội bộ, Public IP, Instance Type, IAM Role temporary credentials).

5. Phương thức kết nối & Quản trị EC2
So sánh SSH truyền thống, EC2 Instance Connect và SSM Session Manager
SSH / RDP truyền thống
Yêu cầu kết nốiPort 22 (Linux) hoặc Port 3389 (Windows). Cần máy có Public IP hoặc thông qua Bastion Host trong Public Subnet.
Xác thựcDùng cặp Key Pair (.pem / .ppk). Quản trị viên phải chịu rủi ro mất hoặc lộ lọt Private Key.
EC2 Instance Connect
Cơ chế hoạt độngĐẩy 1 Public Key tạm thời (thời hạn 60 giây) trực tiếp vào Instance Metadata qua AWS API.
Ưu điểmKết nối trực tiếp từ trình duyệt trên AWS Console hoặc qua AWS CLI mà không cần chia sẻ file private key dài hạn. Vẫn cần mở port 22.
AWS Systems Manager Session Manager (Khuyên dùng)
Bảo mật cao nhấtKHÔNG CẦN MỞ PORT 22, không cần Public IP, không cần Bastion Host, không cần Key Pair.
Cơ chếMáy chủ cài SSM Agent + gắn IAM Role có quyền SSM. Kết nối qua kênh bảo mật HTTPS outbound tới AWS SSM service. Kiểm soát và ghi log toàn bộ lệnh gõ qua CloudTrail & S3.

6. EC2 Placement Groups (Nhóm phân bổ phần cứng)
Kiểm soát vị trí vật lý của các instances trên rack máy chủ AWS
Cluster Placement Group
Gom tất cả các instances vào cùng 1 rack vật lý trong 1 Availability Zone duy nhất. Đem lại độ trễ mạng cực thấp (< 1ms) và băng thông mạng tối đa (10Gbps - 100Gbps). Rủi ro: Nếu rack phần cứng gặp sự cố, tất cả instances cùng chết. Phù hợp Big Data HPC, MPI.
Spread Placement Group
Phân tán tuyệt đối từng instance ra các rack phần cứng vật lý hoàn toàn khác nhau (tối đa 7 instances trên mỗi AZ). Tối đa hóa khả năng chịu lỗi phần cứng. Dành cho các máy chủ tối quan trọng (Critical Applications, Primary/Standby DB).
Partition Placement Group
Chia AZ thành nhiều partitions độc lập (tối đa 7 partitions/AZ, mỗi partition chứa hàng trăm instance). Các partition không dùng chung rack vật lý. Khi 1 partition lỗi, các partition khác vẫn an toàn. Dành riêng cho Hadoop, HDFS, Cassandra, Kafka clusters.
Lưu ý thi cử
Không thể gộp hoặc di chuyển một instance đang tồn tại vào một Placement Group trừ khi dùng CLI stop instance, sửa placement group rồi start lại. Cluster không thể trải dài qua nhiều AZs!

Bổ sung hay gặp trong đề thi SAA-C03
Những chi tiết thực chiến hay làm thí sinh mất điểm
Cờ "Delete on Termination"
Mặc định khi tạo instance, Root EBS Volume được bật thuộc tính DeleteOnTermination = true (sẽ bị xóa khi xóa instance). Các ổ đĩa EBS phụ gắn thêm (Attached Volumes) mặc định là false (vẫn tồn tại sau khi terminate instance).
Termination Protection
Tính năng khóa an toàn bảo vệ instance khỏi việc bị vô tình nhấn "Terminate" trên AWS Console hoặc gọi API. Muốn xóa, quản trị viên bắt buộc phải vào cấu hình tắt cờ Termination Protection trước.
Elastic IP vs Public IPv4
Public IPv4 mặc định của EC2 sẽ bị thay đổi mỗi lần Stop và Start lại instance. Elastic IP là địa chỉ IPv4 cố định. Tuy nhiên trong kiến trúc tốt của AWS, nên dùng Application Load Balancer (ALB) kết hợp Route 53 thay vì gán trực tiếp Elastic IP vào EC2.
Spot Fleet & Spot Block
Spot Fleet tự động duy trì một tập hợp các Spot Instances và On-Demand Instances theo chiến lược (lowestPrice, diversified, capacityOptimized) nhằm đạt mục tiêu dung lượng (Target Capacity) với chi phí thấp nhất.

7. Nguyên tắc vàng — SAA-C03
Ghi nhớ 4 nguyên tắc cốt lõi về EC2 Compute
  • 1
    Tuyệt đối không lưu Access Keys trên EC2Luôn gắn IAM Role (Instance Profile) cho EC2 để máy chủ tự động nhận credentials ngắn hạn từ STS, không bao giờ nhúng AWS_ACCESS_KEY_ID vào source code hoặc disk.
  • 2
    Bảo mật 3 tầng với Security Group ReferenceĐặt Web/App server trong Private Subnet. Cấu hình Security Group của EC2 chỉ chấp nhận Inbound port 80/443 từ Security Group của ALB, chặn mọi truy cập trực tiếp từ Internet.
  • 3
    Quản trị an toàn bằng SSM Session ManagerƯu tiên SSM Session Manager để thay thế SSH/Bastion Host: không cần mở port 22, không cần Public IP và ghi vết audit toàn bộ lệnh người dùng.
  • !
    Bắt buộc nâng cấp lên IMDSv2Luôn cấu hình HttpTokens=required (IMDSv2) cho EC2 instance trong bài toán bảo mật ngân hàng/doanh nghiệp để triệt tiêu nguy cơ trích xuất IAM credentials qua lỗ hổng SSRF.
