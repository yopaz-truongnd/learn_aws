2. Các mô hình thanh toán (Purchasing Options) 2. EC2 Purchasing Options
Chiến lược tối ưu hóa chi phí (Cost Optimization) trong đề thi SAA-C03 Cost optimization strategies for SAA-C03
Linh hoạt & Tạm thời Flexible & Short-Term
On-Demand Trả theo giây/giờ sử dụng thực tế. Không cần cam kết trước. Chi phí cao nhất nhưng linh hoạt nhất cho workload mới, không dự đoán trước được thời gian chạy. Pay for compute capacity per second or hour with no upfront commitments. Highest cost per unit, best for unpredictable, short-term workloads.
Spot Instances Đấu giá dung lượng máy chủ nhàn rỗi của AWS. Giảm giá tới 90% so với On-Demand. Có thể bị AWS thu hồi bất kỳ lúc nào với cảnh báo trước 2 phút. Dành cho Batch jobs, Stateless web app, Rendering video. Không dùng cho DB hoặc critical workloads! Bid on spare AWS compute capacity. Up to 90% discount over On-Demand. Instances can be reclaimed at any time with a 2-minute warning. Ideal for batch jobs, stateless web tiers, video rendering. Never for databases!
Capacity Reservations Giữ chỗ trước phần cứng trong một AZ cụ thể. Không cần cam kết 1-3 năm. Tính phí theo giá On-Demand dù có chạy instance hay không. Reserve compute capacity in a specific AZ without 1-3 year commitments. Charged On-Demand rate whether instances are actively running or idle.
Cam kết dài hạn (1 hoặc 3 năm) Long-Term Commitments (1 or 3 Years)
Reserved Instances (RI) Cam kết 1 hoặc 3 năm. Giảm tới 72%.
• Standard RI: Không đổi được họ instance.
• Convertible RI: Được đổi họ instance, OS, tenancy (giảm giá ít hơn).
• Hình thức: All Upfront, Partial Upfront, No Upfront. 1 or 3-year commitment. Up to 72% discount.
• Standard RI: Cannot change instance family.
• Convertible RI: Can change instance family, OS, tenancy (lower discount).
• Options: All Upfront, Partial Upfront, No Upfront.
Savings Plans Cam kết chi tiêu theo mức tiền cố định mỗi giờ (ví dụ $10/h) trong 1 hoặc 3 năm. Linh hoạt vượt trội so với RI: tự động áp dụng khi chuyển đổi giữa các thế hệ máy chủ EC2, AWS Fargate và AWS Lambda! Commit to a fixed hourly spend (e.g. $10/hr) for 1 or 3 years. Outstanding flexibility over RIs: applies automatically across EC2 instance generations, AWS Fargate, and AWS Lambda!
Cách ly phần cứng (Hardware Isolation) Hardware Isolation & Tenancy
Dedicated Hosts Thuê nguyên một máy chủ vật lý riêng biệt của AWS. Kiểm soát trực tiếp số core/socket vật lý để tuân thủ giấy phép phần mềm theo core (BYOL: Bring Your Own License) và quy định pháp lý khắt khe. Physical server dedicated entirely to your use. Complete control over sockets and physical cores to support core-bound software licensing (BYOL) and strict compliance mandates.
Dedicated Instances Chạy trên phần cứng dành riêng cho một tài khoản khách hàng, nhưng AWS quản lý vị trí socket. Tính phí thêm theo mỗi giờ chạy instance. Instances running on hardware dedicated to a single customer, but socket layout is managed by AWS. Billed an additional hourly tenancy fee.

Instead of opening IP CIDR blocks, EC2 SG only authorizes traffic originating from the ALB SG!

5. Phương thức kết nối & Quản trị EC2 5. EC2 Connection Methods & Administration
So sánh SSH truyền thống, EC2 Instance Connect và SSM Session Manager Comparing traditional SSH, EC2 Instance Connect, and SSM Session Manager
SSH / RDP truyền thống
Yêu cầu kết nối Port 22 (Linux) hoặc Port 3389 (Windows). Cần máy có Public IP hoặc thông qua Bastion Host trong Public Subnet. Port 22 (Linux) or Port 3389 (Windows). Requires Public IP or access via a Bastion Host in a Public Subnet.
Xác thực Dùng cặp Key Pair (.pem / .ppk). Quản trị viên phải chịu rủi ro mất hoặc lộ lọt Private Key. Uses Key Pair files (.pem / .ppk). Risk of private key misplacement or exposure.
EC2 Instance Connect
Cơ chế hoạt động Đẩy 1 Public Key tạm thời (thời hạn 60 giây) trực tiếp vào Instance Metadata qua AWS API. Pushes an ephemeral Public Key (60s lifetime) directly into Instance Metadata via AWS API.
Ưu điểm Kết nối trực tiếp từ trình duyệt trên AWS Console hoặc qua AWS CLI mà không cần chia sẻ file private key dài hạn. Vẫn cần mở port 22. Browser-based console connection without sharing permanent private keys. Still requires port 22 open.
AWS Systems Manager Session Manager (Khuyên dùng)
Bảo mật cao nhất KHÔNG CẦN MỞ PORT 22, không cần Public IP, không cần Bastion Host, không cần Key Pair. NO OPEN PORT 22, no Public IP needed, no Bastion Host, no SSH Key Pairs.
Cơ chế Máy chủ cài SSM Agent + gắn IAM Role có quyền SSM. Kết nối qua kênh bảo mật HTTPS outbound tới AWS SSM service. Kiểm soát và ghi log toàn bộ lệnh gõ qua CloudTrail & S3. SSM Agent + attached IAM Role. Secure outbound HTTPS communication to AWS SSM service. Full command auditing via CloudTrail & S3.

6. EC2 Placement Groups (Nhóm phân bổ phần cứng) 6. EC2 Placement Groups
Kiểm soát vị trí vật lý của các instances trên rack máy chủ AWS Control physical instance placement across underlying AWS server racks
Cluster Placement Group
Gom tất cả các instances vào cùng 1 rack vật lý trong 1 Availability Zone duy nhất. Đem lại độ trễ mạng cực thấp (< 1ms) và băng thông mạng tối đa (10Gbps - 100Gbps). Rủi ro: Nếu rack phần cứng gặp sự cố, tất cả instances cùng chết. Phù hợp Big Data HPC, MPI.
Packs instances close together inside a single AZ on the same hardware rack. Delivers ultra-low latency (< 1ms) and 10–100Gbps bandwidth. Risk: Entire group fails if rack hardware crashes. Ideal for HPC, MPI big data.
Spread Placement Group
Phân tán tuyệt đối từng instance ra các rack phần cứng vật lý hoàn toàn khác nhau (tối đa 7 instances trên mỗi AZ). Tối đa hóa khả năng chịu lỗi phần cứng. Dành cho các máy chủ tối quan trọng (Critical Applications, Primary/Standby DB).
Strictly spreads each instance across distinct hardware racks (max 7 instances per AZ per group). Maximizes fault isolation for mission-critical apps and Primary/Standby DB setups.
Partition Placement Group
Chia AZ thành nhiều partitions độc lập (tối đa 7 partitions/AZ, mỗi partition chứa hàng trăm instance). Các partition không dùng chung rack vật lý. Khi 1 partition lỗi, các partition khác vẫn an toàn. Dành riêng cho Hadoop, HDFS, Cassandra, Kafka clusters.
Divides an AZ into logical partitions (up to 7 partitions/AZ, hundreds of instances per partition). Partitions never share hardware racks. Ideal for distributed Hadoop, HDFS, Cassandra, and Kafka clusters.
Lưu ý thi cử Exam Nuances
Không thể gộp hoặc di chuyển một instance đang tồn tại vào một Placement Group trừ khi dùng CLI stop instance, sửa placement group rồi start lại. Cluster không thể trải dài qua nhiều AZs!
You cannot merge an existing instance into a placement group without stopping it first, updating placement via CLI, and starting it again. Cluster Placement Groups CANNOT span multiple AZs!

Cờ "Delete on Termination" "Delete on Termination" Flag
Mặc định khi tạo instance, Root EBS Volume được bật thuộc tính DeleteOnTermination = true (sẽ bị xóa khi xóa instance). Các ổ đĩa EBS phụ gắn thêm (Attached Volumes) mặc định là false (vẫn tồn tại sau khi terminate instance).
By default at launch, the Root EBS Volume has DeleteOnTermination = true (deleted when instance is terminated). Additional attached EBS volumes default to false (preserved after termination).
Termination Protection
Tính năng khóa an toàn bảo vệ instance khỏi việc bị vô tình nhấn "Terminate" trên AWS Console hoặc gọi API. Muốn xóa, quản trị viên bắt buộc phải vào cấu hình tắt cờ Termination Protection trước.
Safety lock protecting instances from accidental termination via AWS Console or API. Must explicitly disable Termination Protection before termination is allowed.
Elastic IP vs Public IPv4
Public IPv4 mặc định của EC2 sẽ bị thay đổi mỗi lần Stop và Start lại instance. Elastic IP là địa chỉ IPv4 cố định. Tuy nhiên trong kiến trúc tốt của AWS, nên dùng Application Load Balancer (ALB) kết hợp Route 53 thay vì gán trực tiếp Elastic IP vào EC2.
Default Public IPv4 address changes upon instance Stop and Start. Elastic IP provides a static IPv4 address. Architectural best practice: use ALB + Route 53 rather than assigning Elastic IPs directly to EC2 instances.
Spot Fleet & Spot Block
Spot Fleet tự động duy trì một tập hợp các Spot Instances và On-Demand Instances theo chiến lược (lowestPrice, diversified, capacityOptimized) nhằm đạt mục tiêu dung lượng (Target Capacity) với chi phí thấp nhất.
Spot Fleet automates maintaining a collection of Spot and On-Demand instances based on strategies (lowestPrice, diversified, capacityOptimized) to satisfy Target Capacity at minimum cost.

7. Nguyên tắc vàng — SAA-C03 7. Golden Rules — SAA-C03
Ghi nhớ 4 nguyên tắc cốt lõi về EC2 Compute 4 essential compute principles to memorize
  • 1
    Tuyệt đối không lưu Access Keys trên EC2 Never Store Access Keys on EC2 Instances Luôn gắn IAM Role (Instance Profile) cho EC2 để máy chủ tự động nhận credentials ngắn hạn từ STS, không bao giờ nhúng AWS_ACCESS_KEY_ID vào source code hoặc disk. Always attach an IAM Role (Instance Profile) to EC2 so instances automatically receive short-term STS credentials. Never embed static AWS_ACCESS_KEY_ID in disk or source code.
  • 2
    Bảo mật 3 tầng với Security Group Reference 3-Tier Defense with Security Group References Đặt Web/App server trong Private Subnet. Cấu hình Security Group của EC2 chỉ chấp nhận Inbound port 80/443 từ Security Group của ALB, chặn mọi truy cập trực tiếp từ Internet. Place backend servers in Private Subnets. Configure EC2 Security Groups to accept inbound traffic only from the ALB's Security Group ID, eliminating direct Internet exposure.
  • 3
    Quản trị an toàn bằng SSM Session Manager Secure Server Management via SSM Session Manager Ưu tiên SSM Session Manager để thay thế SSH/Bastion Host: không cần mở port 22, không cần Public IP và ghi vết audit toàn bộ lệnh người dùng. Adopt SSM Session Manager over SSH/Bastion Hosts: zero open port 22, no Public IP requirements, and centralized audit logging of all executed commands.
  • !
    Bắt buộc nâng cấp lên IMDSv2 Mandate IMDSv2 for Security Compliance Luôn cấu hình HttpTokens=required (IMDSv2) cho EC2 instance trong bài toán bảo mật ngân hàng/doanh nghiệp để triệt tiêu nguy cơ trích xuất IAM credentials qua lỗ hổng SSRF. Enforce HttpTokens=required (IMDSv2) on all EC2 instances to neutralize SSRF vulnerabilities attempting to extract IAM STS credentials.
