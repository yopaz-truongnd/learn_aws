📁 1. Amazon FSx Series 📁 1. Amazon FSx Series
Là gì? (Definition) What is it?

Dịch vụ hệ thống tệp được quản lý hoàn toàn (Fully Managed) dành cho các giải pháp lưu trữ của bên thứ ba: FSx for Windows, FSx for Lustre, FSx for NetApp ONTAP và FSx for OpenZFS.

Fully managed third-party file system service offering FSx for Windows, FSx for Lustre, FSx for NetApp ONTAP, and FSx for OpenZFS with native feature parity.

Dùng khi nào? (When to use) When to use?

Khi doanh nghiệp chuyển dịch (Lift & Shift) các ứng dụng phụ thuộc chặt chẽ vào Microsoft Windows (SMB/AD), hoặc khi chạy tác vụ tính toán hiệu năng cao HPC, Machine Learning, EDA, phân tích gen sinh học cần throughput hàng trăm GB/s.

When migrating workloads tightly coupled with Windows ecosystem (SMB/NTFS/AD), or running HPC, Machine Learning, EDA, and genomic analysis requiring hundreds of GB/s throughput.

Khác gì? (Key Differences) Key Differences

Khác với EFS (chỉ hỗ trợ giao thức NFSv4 trên Linux), FSx for Windows hỗ trợ native SMB, DFS Namespaces và Microsoft Active Directory. FSx for Lustre có thể đọc và đồng bộ hóa trực tiếp với Amazon S3 hai chiều.

Unlike EFS (Linux-only POSIX NFSv4), FSx for Windows supports native SMB, DFS Namespaces, and Active Directory. FSx for Lustre bridges seamlessly with Amazon S3 bidirectionally.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: Đề bài nhắc tới "Windows File Share" + "SMB" mà chọn EFS là sai ngay → Phải chọn FSx for Windows. Với Lustre, phân biệt Scratch (tạm thời, không HA, rẻ) vs Persistent (lưu trữ lâu dài, tự sao chép trong cùng AZ).

⚠️ Exam Trap: Choosing EFS for "Windows File Share" + "SMB" is an instant failure → Must choose FSx for Windows. For Lustre, know Scratch (burst, temporary, no HA) vs Persistent (long-term, replicated in same AZ).

🌉 2. AWS Storage Gateway 🌉 2. AWS Storage Gateway
Là gì? (Definition) What is it?

Dịch vụ cầu nối lưu trữ lai (Hybrid Cloud Storage) kết nối hạ tầng on-premises với dịch vụ lưu trữ đám mây AWS thông qua máy ảo ảo hóa (VMware ESXi, Hyper-V, KVM) hoặc phần cứng chuyên dụng (Hardware Appliance).

Hybrid cloud storage service connecting on-premises IT environments seamlessly with AWS storage infrastructure via virtual machines (VMware ESXi, Hyper-V, KVM) or hardware appliances.

Dùng khi nào? (When to use) When to use?

Khi doanh nghiệp muốn tận dụng lưu trữ vô hạn, giá rẻ của AWS (S3, EBS Snapshots, Glacier) nhưng hệ thống on-premises không được phép thay đổi mã nguồn và bắt buộc phải giao tiếp qua giao thức chuẩn (NFS, SMB, iSCSI).

When on-prem applications need unlimited, low-cost AWS storage (S3, EBS Snapshots, Glacier) without modifying existing code, communicating strictly via standard protocols (NFS, SMB, iSCSI).

Khác gì? (Key Differences) Key Differences

Gồm 3 họ chính:
• S3 File Gateway: Tệp on-prem → S3 Object (NFS/SMB).
• Volume Gateway: Khối đĩa iSCSI. Cached (data chính trên S3) vs Stored (data chính ở on-prem).
• Tape Gateway: Giả lập thư viện băng từ (VTL) lưu vào Glacier.

3 distinct architectures:
• S3 File Gateway: Files → S3 Objects (NFS/SMB).
• Volume Gateway: Block storage (iSCSI). Cached (primary in S3) vs Stored (primary on-prem).
• Tape Gateway: Virtual Tape Library (VTL) to Glacier.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: Nếu đề bài nhấn mạnh "ngay cả khi đứt kết nối internet, máy chủ on-premise vẫn phải đọc/ghi được toàn bộ dữ liệu" → Bắt buộc là Volume Gateway (Stored Volumes), không được chọn Cached Volumes.

⚠️ Exam Trap: If the prompt emphasizes "on-premise servers must maintain full read/write access to the entire dataset even during internet outages" → Must choose Volume Gateway (Stored Volumes).

❄️ 3. AWS Snow Family ❄️ 3. AWS Snow Family
Là gì? (Definition) What is it?

Bộ thiết bị phần cứng vật lý chống va đập, bảo mật cao được AWS vận chuyển trực tiếp đến khách hàng nhằm di chuyển dữ liệu ngoại tuyến (Offline Data Migration) và xử lý tính toán tại biên (Edge Computing).

Collection of physical, ruggedized, secure hardware devices shipped by AWS for offline data migration and edge computing where network connectivity is impossible or cost-prohibitive.

Dùng khi nào? (When to use) When to use?

Khi dung lượng dữ liệu quá lớn (hàng chục TB đến hàng trăm PB) mà băng thông mạng mất hàng tháng để truyền tải, hoặc triển khai tính toán di động trên tàu biển, giàn khoan dầu khí, vùng sâu vùng xa không có internet.

When data scale is huge (tens of TBs to hundreds of PBs) taking months over public internet, or deploying mobile compute on ships, oil rigs, and remote edge sites lacking internet access.

Khác gì? (Key Differences) Key Differences

• Snowcone: Siêu nhỏ gọn (2.1 kg), 8 TB – 14 TB, chạy pin.
• Snowball Edge: 80 TB – 210 TB, có bản Storage Optimized và Compute Optimized (kèm GPU).
• Snowmobile: Xe container 45-foot, di chuyển dữ liệu tới 100 PB/xe.

• Snowcone: Ultra-portable (2.1 kg), 8 TB – 14 TB, battery option.
• Snowball Edge: 80 TB – 210 TB, Storage Optimized & Compute Optimized (with GPU).
• Snowmobile: 45-foot container truck moving up to 100 PB per unit.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: Snowball không import trực tiếp vào Glacier! Snowball chỉ nạp dữ liệu vào Amazon S3, sau đó bạn phải thiết lập S3 Lifecycle Policy để chuyển dữ liệu vào Glacier.

⚠️ Exam Trap: Snowball cannot import directly into S3 Glacier! It only imports data into Amazon S3 buckets; you must use an S3 Lifecycle Policy to transition objects to Glacier.

📐 Công thức vàng: Khi nào chọn Snowball thay vì truyền mạng? 📐 Golden Formula: When to choose Snowball over Network?

Thời gian truyền tải dữ liệu lý thuyết qua đường truyền mạng:

Theoretical data transfer time over network connection:

Thời gian (giây) = [Dung lượng (Bytes) × 8] / Băng thông (bps)
Ví dụ kinh điển trong đề thi: Cần di chuyển 100 TB qua đường truyền 100 Mbps (sử dụng 80% hiệu dụng):
• $T \approx (100 \times 10^{12} \times 8) / (80 \times 10^6) \approx 10.000.000\text{ giây} \approx \mathbf{115\text{ ngày}}$ (> 3.8 tháng!).
• Thời gian vận chuyển Snowball Edge: Yêu cầu → Giao nhận → Copy → Trả về → Nạp vào S3 chỉ mất khoảng 5 – 7 ngày.
👉 Nguyên tắc đề thi: Nếu thời gian truyền mạng lớn hơn 1 tuần → Đáp án đúng luôn là AWS Snowball Edge. Classic Exam Example: Transferring 100 TB over a 100 Mbps link (at 80% utilization):
• $T \approx (100 \times 10^{12} \times 8) / (80 \times 10^6) \approx 10,000,000\text{ sec} \approx \mathbf{115\text{ days}}$ (> 3.8 months!).
• Snowball shipping cycle: Request → Delivery → Ingest → Return → S3 Load takes roughly 5 – 7 days.
👉 Exam Rule: If network transfer time exceeds 1 week → The correct answer is always AWS Snowball Edge.
🔄 AWS DataSync vs AWS Snow Family 🔄 AWS DataSync vs AWS Snow Family

• AWS DataSync: Chuyển dữ liệu trực tuyến qua mạng (Online via Internet hoặc AWS Direct Connect). Hỗ trợ lập lịch tự động, kiểm tra tính toàn vẹn (TLS + Checksum), băng thông tối đa 10 Gbps.
• Snow Family: Chuyển dữ liệu ngoại tuyến (Offline) bằng phần cứng vật lý khi không có mạng hoặc mạng quá chậm.

• AWS DataSync: Online network transfer (via Internet or AWS Direct Connect). Supports automated scheduling, TLS encryption + checksum integrity, up to 10 Gbps.
• Snow Family: Offline physical transfer via secure ruggedized appliances when network is absent or too slow.

🔴 1. FSx for Lustre: Scratch vs Persistent File Systems 🔴 1. FSx for Lustre: Scratch vs Persistent File Systems

• Scratch: Thiết kế cho xử lý dữ liệu tạm thời, ngắn hạn. Dữ liệu không được sao chép dự phòng (không có HA). Nếu máy chủ file bị lỗi, dữ liệu chưa kịp xuất về S3 sẽ bị mất vĩnh viễn. Đổi lại chi phí cực thấp, throughput cực cao.
• Persistent: Thiết kế cho dữ liệu dài hạn. Tự động sao chép dự phòng các tệp tin trong cùng một Availability Zone. Nếu một máy chủ file gặp sự cố, hệ thống tự động thay thế và không làm gián đoạn dữ liệu.

• Scratch: Designed for temporary, burst processing. Data is not replicated (no HA). If a storage server fails, uncommitted data to S3 is permanently lost. Trade-off: lowest cost, maximum throughput.
• Persistent: Designed for long-term workloads. Automatically replicates data within the same Availability Zone. Highly available with automatic failover if a storage server fails.

🔴 2. Storage Gateway Hardware Appliance 🔴 2. Storage Gateway Hardware Appliance

Thông thường Storage Gateway được cài đặt dưới dạng file ảnh ảo hóa (VM) trên VMware ESXi, Microsoft Hyper-V hoặc Linux KVM. Tuy nhiên, nếu doanh nghiệp hoàn toàn không có hạ tầng ảo hóa (chỉ có máy chủ vật lý bare-metal), AWS cung cấp Storage Gateway Hardware Appliance (máy chủ vật lý đóng sẵn đặt trong tủ rack).

Storage Gateway is typically deployed as a software VM image on VMware ESXi, Microsoft Hyper-V, or Linux KVM. However, if an organization lacks any virtualization infrastructure (bare-metal servers only), AWS provides a pre-configured rack-mountable Storage Gateway Hardware Appliance.

🔴 3. Bảo mật Snowball & Tiêu chuẩn xóa dữ liệu NIST 800-88 🔴 3. Snowball Security & NIST 800-88 Cryptographic Erasure

Toàn bộ thiết bị Snow Family được mã hóa tự động bằng khóa KMS 256-bit do khách hàng quản lý. Thiết bị sử dụng nhãn vận chuyển bằng màn hình mực điện tử (E-ink) tự động đổi địa chỉ về AWS khi hoàn tất copy. Khi về đến trung tâm dữ liệu AWS, sau khi nạp xong dữ liệu vào S3, thiết bị sẽ được tẩy xóa bảo mật chuẩn NIST 800-88 trước khi chuyển cho khách hàng khác.

All Snow Family devices are automatically encrypted with customer-managed 256-bit KMS keys. Devices feature an E-ink shipping label that auto-updates upon copy completion. Once returned and ingested into S3, AWS sanitizes the hardware following strict NIST 800-88 cryptographic erasure standards.

🔴 4. AWS Transfer Family: SFTP/FTPS không máy chủ 🔴 4. AWS Transfer Family: Serverless SFTP/FTPS Endpoints

Khi đối tác bên ngoài yêu cầu truyền tệp qua giao thức SFTP, FTPS hoặc FTP mà dữ liệu cần nằm an toàn trong Amazon S3 hoặc Amazon EFS → Không tự dựng EC2 chạy OpenSSH/ProFTPD! Sử dụng ngay AWS Transfer Family (hoàn toàn Serverless, tự co giãn, không cần vá lỗi OS).

When external business partners require file exchanges via SFTP, FTPS, or FTP and files must reside securely in Amazon S3 or Amazon EFS → Never manage EC2 with OpenSSH/ProFTPD! Leverage AWS Transfer Family (fully managed, serverless, auto-scaling, zero OS patching).

6. Nguyên tắc vàng ra quyết định kiến trúc — SAA-C03 6. Golden Architectural Decision Rules — SAA-C03
Các quy tắc bất biến giúp loại trừ ngay phương án sai trong 30 giây Inviolable rules to eliminate incorrect multiple-choice options in 30 seconds
1
Windows Native File Sharing = Luôn là FSx for Windows Windows Native File Sharing = Always FSx for Windows
EFS không hỗ trợ giao thức SMB hay tích hợp Microsoft Active Directory. Mọi câu hỏi có cụm từ "SMB", "Active Directory", "NTFS Permissions", "DFS Namespaces" → Chọn ngay FSx for Windows File Server.
EFS does not support SMB or Active Directory integration. Any question featuring "SMB", "Active Directory", "NTFS Permissions", or "DFS Namespaces" → Immediately select FSx for Windows.
2
HPC / Machine Learning kết hợp Amazon S3 = Luôn là FSx for Lustre HPC / Machine Learning with Amazon S3 = Always FSx for Lustre
Khi cần hệ thống file POSIX Linux có thể đọc trực tiếp các đối tượng trong S3 bucket với throughput hàng trăm GB/s và xuất kết quả ngược lại S3 → Chọn ngay FSx for Lustre.
When requiring a POSIX Linux file system that directly reads objects from an S3 bucket with hundreds of GB/s throughput and writes results back → Always choose FSx for Lustre.
3
Di chuyển vật lý không vào thẳng Glacier Physical Offline Ingestion Never Directly Targets Glacier
AWS Snowball Edge chỉ có thể nạp dữ liệu vào các bucket Amazon S3 Standard. Để lưu vào Glacier, kiến trúc sư bắt buộc phải cấu hình thêm S3 Lifecycle Rule sau khi dữ liệu đã lên cloud.
AWS Snowball Edge can only import data into Amazon S3 Standard buckets. Archiving to Glacier strictly requires configuring an S3 Lifecycle Rule post-ingestion.
4
Thay thế băng từ cũ không đổi code = Tape Gateway (VTL) Legacy Tape Replacement Without Code Change = Tape Gateway (VTL)
Khi doanh nghiệp muốn ngừng mua băng từ vật lý LTO đắt đỏ nhưng không muốn thay đổi quy trình sao lưu hay phần mềm backup hiện tại → Chọn Storage Gateway: Tape Gateway.
When replacing expensive physical LTO magnetic tapes without disrupting current backup software pipelines → Choose Storage Gateway: Tape Gateway.
