🔴 Phân biệt nhanh bộ 3: CloudWatch vs CloudTrail vs AWS Config 🔴 The Governance Triad: CloudWatch vs CloudTrail vs AWS Config • CloudWatch = Hiệu năng & Giám sát (Metrics, Logs, Alarms): Trả lời câu hỏi "Hệ thống đang hoạt động như thế nào?" (CPU, Ram, Disk, Network, Error rate).
• CloudTrail = Kiểm toán & Lịch sử gọi API (Auditing): Trả lời câu hỏi "AI đã làm GÌ, VÀO LÚC NÀO, và TỪ ĐÂU?" (Ghi nhận user, IP, API call như `TerminateInstances`, `DeleteBucket`).
• AWS Config = Tuân thủ cấu hình & Dòng thời gian tài nguyên (Compliance): Trả lời câu hỏi "Tài nguyên có ĐÚNG TIÊU CHUẨN bảo mật không và đã THAY ĐỔI CẤU HÌNH như thế nào qua thời gian?" (Ví dụ: SG có bị mở port 22 cho 0.0.0.0/0 không).
• RAM & Dung lượng đĩa EC2 không có mặc định: CloudWatch mặc định chỉ đo CPU, Network, Disk I/O. Muốn đo % Memory và Free Disk Space → Bắt buộc cài Unified CloudWatch Agent.
• Tự động khắc phục vi phạm bảo mật (Remediation): AWS Config phát hiện non-compliant → Kích hoạt SSM Automation Document để tự động sửa lỗi (như đóng public S3 bucket, thu hồi IAM key). • CloudWatch = Performance & Observability (Metrics, Logs, Alarms): Answers "How is my system operating right now?" (CPU, RAM, latency, logs, error rates).
• CloudTrail = API Auditing & Accountability: Answers "WHO did WHAT, WHEN, and from WHERE?" (Records caller identity, IP, and API actions like `TerminateInstances`, `DeleteBucket`).
• AWS Config = Configuration Compliance & History: Answers "Are my resources compliant with security baselines, and HOW has configuration changed over time?" (e.g. was port 22 exposed to 0.0.0.0/0).
• EC2 Memory & Disk Usage are NOT Default Metrics: CloudWatch hypervisor only sees CPU/Network/Disk I/O. Measuring OS-level Memory/Disk → Must install Unified CloudWatch Agent.
• Automated Security Remediation: AWS Config detects non-compliance → Triggers SSM Automation Documents to auto-remediate (e.g. revoke public S3 access, disable stale keys).

📊 1. Amazon CloudWatch 📊 1. Amazon CloudWatch
Là gì? (Definition) What is it?

Dịch vụ giám sát hiệu năng và quan sát hệ thống (Observability). Thu thập số liệu thống kê (Metrics), tập trung hóa nhật ký ứng dụng (Logs) và kích hoạt cảnh báo (Alarms).

Monitoring and observability service collecting performance metrics, centralizing log data, and triggering automated alarms across AWS resources and on-premise applications.

Dùng khi nào? (When to use) When to use?

Theo dõi mức sử dụng CPU/Network/RAM, kích hoạt co giãn Auto Scaling (Scale-out khi CPU > 70%), khởi động lại máy chủ EC2 lỗi tự động (EC2 Status Check recovery), tìm kiếm lỗi trong log.

Tracking CPU/Network/RAM loads, triggering Auto Scaling events, automating EC2 instance recovery upon system check failures, and running log analytics queries.

Khác gì? (Key Differences) Key Differences

Mặc định đo đạc mỗi 5 phút (Basic Monitoring). Có thể bật Detailed Monitoring (1 phút - có phí). Dữ liệu metric lưu trữ tối đa 15 tháng.

Default frequency is 5 minutes (Basic Monitoring). Optional Detailed Monitoring measures every 1 minute. Metric data points are retained for 15 months.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: Đề thi hỏi về đo đạc Memory Utilization hoặc Disk Space trên EC2 mà không nhắc đến CloudWatch Agent là bẫy! EC2 Hypervisor không thể nhìn vào bên trong RAM của OS.

⚠️ Exam Trap: Scenarios asking for Memory Utilization or Disk Space on EC2 without mentioning the CloudWatch Agent are traps! The EC2 hypervisor cannot inspect guest OS RAM.

📜 2. AWS CloudTrail 📜 2. AWS CloudTrail
Là gì? (Definition) What is it?

Dịch vụ kiểm toán và ghi vết mọi thao tác gọi hàm API trên tài khoản AWS (từ AWS Console, CLI, SDK và các dịch vụ tự động gọi nhau).

Governance, compliance, and auditing service logging every API call executed across your AWS account (from Console, CLI, SDKs, and automated service interactions).

Dùng khi nào? (When to use) When to use?

Điều tra sự cố bảo mật (ai đã mở Security Group, ai đã xóa database), đối soát kiểm toán tuân thủ pháp lý, phát hiện hành vi bất thường (CloudTrail Insights) và lưu vết lâu dài vào S3.

Security investigations (who modified security groups, who deleted resources), compliance audits, anomaly detection (CloudTrail Insights), and immutable audit storage in S3.

Khác gì? (Key Differences) Key Differences

Lịch sử sự kiện (Event History) lưu miễn phí 90 ngày. Muốn lưu trữ lâu dài bắt buộc tạo một Trail để xuất file log nén nạp vào Amazon S3 bucket và CloudWatch Logs.

Event History is retained free for 90 days. Long-term archival requires configuring a Trail delivering compressed audit logs into an Amazon S3 bucket and CloudWatch Logs.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: Để đảm bảo tệp log của CloudTrail trong S3 không bị chỉnh sửa hay xóa trộm bởi kẻ xấu → Bật CloudTrail Log File Integrity Validation (dùng mã băm SHA-256) và S3 Object Lock.

⚠️ Exam Trap: To prove to auditors that CloudTrail log files in S3 have not been tampered with or deleted → Enable CloudTrail Log File Integrity Validation (SHA-256) and S3 Object Lock.

⚙️ 3. AWS Config ⚙️ 3. AWS Config
Là gì? (Definition) What is it?

Dịch vụ kiểm tra và theo dõi liên tục trạng thái cấu hình của tài nguyên AWS, đánh giá sự tuân thủ (Compliance) dựa trên các bộ quy tắc bảo mật được thiết lập trước.

Continuous configuration audit and governance service tracking configuration changes over time, evaluating compliance against desired security baselines.

Dùng khi nào? (When to use) When to use?

Đảm bảo các tiêu chuẩn bảo mật doanh nghiệp (ví dụ: mọi ổ EBS phải được mã hóa, mọi S3 bucket phải chặn public access, cổng SSH 22 không được mở ra 0.0.0.0/0), xem lịch sử thay đổi cấu hình.

Enforcing organizational security guardrails (e.g. all EBS volumes must be encrypted, no public S3 buckets, no port 22 open to 0.0.0.0/0) and reviewing configuration timeline history.

Khác gì? (Key Differences) Key Differences

Không kiểm tra "ai gọi lệnh" (việc của CloudTrail), mà kiểm tra "kết quả cấu hình của tài nguyên có hợp chuẩn không". Có khả năng tự động sửa lỗi (Remediation) qua SSM Automation.

Does not track API caller identity (that's CloudTrail's job); inspects "the resulting resource configuration state". Features automated remediation via SSM Automation.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: AWS Config không ngăn chặn hành động (Config chỉ phát hiện vi phạm và báo NON_COMPLIANT). Muốn ngăn chặn triệt để hành động không xảy ra → Phải dùng SCP (AWS Organizations) hoặc IAM Policy!

⚠️ Exam Trap: AWS Config does not prevent actions (it evaluates post-facto and marks NON_COMPLIANT). To actively prevent non-compliant actions → Must use SCPs in AWS Organizations!

💡 Vì sao mô hình này xuất hiện trong đề thi SAA-C03? 💡 Why is this pattern featured in SAA-C03?

• Bảo vệ chủ động (Continuous Governance): Con người có thể vô tình mở một Security Group ra 0.0.0.0/0 hoặc gỡ mã hóa ổ đĩa. AWS Config phát hiện vi phạm trong vòng vài phút.
• Tự động sửa lỗi không cần con người (Automated Remediation): Tích hợp với AWS Systems Manager (SSM) Automation Documents cho phép thực thi kịch bản khắc phục sự cố ngay lập tức.
• Ví dụ đề thi: "Làm thế nào để đảm bảo rằng bất cứ khi nào một bucket S3 mới được tạo mà không bật mã hóa mặc định, nó sẽ tự động được kích hoạt mã hóa SSE-KMS ngay lập tức?" → Cấu hình AWS Config Rule kết hợp SSM Automation Remediation!

• Continuous Governance: Developers can accidentally expose port 22 or remove bucket encryption. AWS Config detects violations within minutes.
• Automated Hands-Off Remediation: Paired with AWS Systems Manager (SSM) Automation Runbooks, security teams can remediate violations without manual tickets.
• Exam Scenario: "How to automatically ensure that whenever an unencrypted S3 bucket is created, it is immediately converted to use default SSE-KMS encryption?" → Configure an AWS Config Rule with SSM Automation Remediation!

4. Nguyên tắc vàng ra quyết định kiến trúc Giám sát & Kiểm toán — SAA-C03 4. Golden Architectural Decision Rules: Monitoring & Auditing — SAA-C03
Các quy tắc bất biến giúp chọn đúng giải pháp kiểm toán trong 30 giây Inviolable rules to identify the correct monitoring solution in 30 seconds
1
Điều tra "Ai gọi lệnh gì" = Luôn là AWS CloudTrail Investigating "Who executed which API call" = Always AWS CloudTrail
Bất kể câu hỏi nào nhắc đến: "ai đã sửa đổi IAM role", "ai đã dừng máy chủ", "truy vết nguồn gốc xâm nhập từ địa chỉ IP nào" → Chọn ngay AWS CloudTrail Event History hoặc CloudTrail Trail.
Whenever a scenario investigates: "who modified IAM policies", "who terminated an instance", or "tracing unauthorized IP access" → Immediately select AWS CloudTrail.
2
Đo RAM / Disk Space trên EC2 = Cài Unified CloudWatch Agent Measuring RAM / Free Disk Space on EC2 = Install Unified CloudWatch Agent
CloudWatch cơ bản không thể đọc RAM hay Disk Space bên trong OS. Mọi câu hỏi yêu cầu tạo Alarm dựa trên mức sử dụng RAM → Phải cài đặt Unified CloudWatch Agent trên instance.
Standard CloudWatch metrics cannot inspect guest OS memory. Any scenario requiring an alarm on RAM utilization → Must install the Unified CloudWatch Agent.
3
Bảo vệ tệp log kiểm toán không bị sửa xóa = Log File Integrity + Object Lock Audit Log Tamper-Proofing = Log File Integrity + Object Lock
Để ngăn chặn hacker hoặc quản trị viên biến chất sửa đổi file log CloudTrail trong S3 → Luôn bật CloudTrail Log File Integrity Validation (SHA-256) và thiết lập S3 Object Lock (WORM).
To prevent rogue admins or attackers from doctoring CloudTrail audit logs in S3 → Always enable CloudTrail Log File Integrity Validation (SHA-256) and S3 Object Lock.
4
Đánh giá cấu hình hợp chuẩn & Tự sửa lỗi = AWS Config Configuration Compliance & Auto-Remediation = AWS Config
Khi cần duy trì tiêu chuẩn bảo mật cho toàn bộ tài nguyên theo thời gian (EBS encryption, S3 Block Public Access, IAM password rules) → Luôn chọn AWS Config Rules + SSM Automation.
When maintaining ongoing security baselines across resources (EBS encryption, S3 Block Public Access, IAM password rules) → Always choose AWS Config Rules + SSM Automation.
