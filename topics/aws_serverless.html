• HTTP API vs REST API: Cần chi phí rẻ nhất (giảm 70%), độ trễ thấp & xác thực JWT → HTTP API. Cần API Keys, Usage Plans, WAF hoặc API Caching → Bắt buộc REST API.
• Cognito User Pools (CUP) vs Identity Pools: CUP = Authentication (Đăng nhập, Sign-up, nhận JWT); Identity Pools = Authorization (Đổi token lấy AWS IAM temporary credentials để gọi thẳng S3/DynamoDB).
• Step Functions: Standard vs Express: Standard chạy tối đa 1 năm, đảm bảo Exactly-once execution; Express chạy tối đa 5 phút, khối lượng lớn > 100.000 msg/s. • 15 minutes: Maximum execution timeout for AWS Lambda. Jobs exceeding 15 minutes → Never choose Lambda; use ECS Fargate, AWS Batch, or EC2.
• 128 MB → 10,240 MB (10 GB): Lambda RAM limits. CPU scales proportionally (at 1,769 MB RAM → allocated 1 full vCPU).
• Provisioned Concurrency = Eliminates Cold Starts 100%: Pre-warms runtime containers for financial/e-commerce workloads demanding strict low p99 latencies.
• HTTP API vs REST API: Lowest cost (70% savings), low latency & native JWT → HTTP API. API Keys, Usage Plans, WAF, or Edge Caching → Strictly REST API.
• Cognito User Pools vs Identity Pools: User Pools = Authentication (Sign-up, sign-in, JWTs); Identity Pools = Authorization (Exchange token for temporary AWS IAM credentials to access S3/DynamoDB directly).
• Step Functions: Standard vs Express: Standard runs up to 1 year with Exactly-once execution; Express runs up to 5 minutes for high-volume streaming > 100,000/s.

⚡ 1. AWS Lambda ⚡ 1. AWS Lambda
Là gì? (Definition) What is it?

Dịch vụ điện toán không máy chủ (Serverless Compute) hướng sự kiện. Cho phép bạn chạy mã nguồn (Python, Node.js, Java, Go, C#) mà không cần cấp phát hay quản lý máy chủ.

Event-driven serverless compute service. Executes application code (Python, Node.js, Java, Go, C#) in response to triggers with zero server provisioning or administration.

Dùng khi nào? (When to use) When to use?

Xử lý các tác vụ ngắn hạn (≤ 15 phút): Cron job tự động, xử lý ảnh khi upload lên S3, backend API không máy chủ kết hợp với API Gateway, xử lý bản ghi luồng Kinesis/DynamoDB.

Short-lived tasks (≤ 15 mins): Scheduled cron jobs, S3 object transformation triggers, serverless REST backends with API Gateway, and streaming event processors.

Khác gì? (Key Differences) Key Differences

Tự động co giãn theo từng yêu cầu (scale-to-zero khi không có traffic → 0 đồng). Thanh toán theo số lượng invocation và thời gian thực thi làm tròn tới mili-giây (ms).

Scales automatically per individual request down to zero (zero idle cost). Billed strictly by execution duration measured in milliseconds and memory consumed.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: Lambda truy cập cơ sở dữ liệu RDS trong VPC riêng tư → Hàm cần gán Subnet & Security Group (dùng Hyperplane ENI). Tránh mở quá nhiều connection trực tiếp → Kết hợp với Amazon RDS Proxy!

⚠️ Exam Trap: Lambda accessing private RDS databases needs VPC Subnets & Security Groups. To prevent exhausting database connection pools → Place Amazon RDS Proxy in between!

🚪 2. Amazon API Gateway 🚪 2. Amazon API Gateway
Là gì? (Definition) What is it?

Dịch vụ quản lý API không máy chủ hoàn toàn, đóng vai trò "cửa ngõ" đón tiếp toàn bộ lưu lượng HTTP/HTTPS/WebSocket từ người dùng và định tuyến an toàn tới các dịch vụ backend.

Fully managed serverless API gateway serving as a front door accepting HTTP/HTTPS/WebSocket traffic at scale, securely routing requests to backend services.

Dùng khi nào? (When to use) When to use?

Tạo các điểm cuối (endpoints) RESTful công khai hoặc nội bộ cho ứng dụng Web/Mobile; bảo vệ backend bằng Rate Limiting, Throttling, API Caching và tường lửa AWS WAF.

Creating public or internal RESTful endpoints for web/mobile apps; protecting downstream backends via Rate Limiting, Throttling, API Caching, and AWS WAF integration.

Khác gì? (Key Differences) Key Differences

Hỗ trợ 3 loại API:
• HTTP API: Chi phí rẻ hơn 70%, độ trễ cực thấp, chuẩn JWT.
• REST API: Đầy đủ tính năng doanh nghiệp (WAF, Usage Plans, API Keys).
• WebSocket API: Giao tiếp 2 chiều thời gian thực.

Offers 3 API flavors:
• HTTP API: 70% cheaper, ultra-low latency, native JWT.
• REST API: Full enterprise features (WAF, Usage Plans, API Keys).
• WebSocket API: Full-duplex persistent connections.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: Khách hàng nhận mã lỗi HTTP 429 Too Many Requests → Do chạm trần Throttling Limits của API Gateway (mặc định 10.000 req/s)! Khắc phục: Bật API Gateway Caching hoặc yêu cầu tăng quota.

⚠️ Exam Trap: Clients receiving HTTP 429 Too Many Requests → Breaching API Gateway Throttling Limits (default 10,000 req/s)! Fix: Enable API Gateway Caching or request a quota increase.

🪜 3. AWS Step Functions 🪜 3. AWS Step Functions
Là gì? (Definition) What is it?

Dịch vụ điều phối luồng công việc trực quan (Visual Workflow Orchestrator) dựa trên mô hình Máy trạng thái (State Machine) viết bằng ngôn ngữ Amazon States Language (JSON).

Low-code visual workflow orchestrator built on State Machines defined in Amazon States Language (JSON), stitching serverless functions and AWS services together.

Dùng khi nào? (When to use) When to use?

Kết nối nhiều hàm Lambda thành chuỗi xử lý tuần tự/song song, xử lý lỗi (Try/Catch/Retry), chờ phê duyệt của con người (Human Approval task) hoặc chạy pipeline thanh toán nhiều bước.

Sequencing multiple Lambda functions into sequential/parallel branches, handling automated retries and compensations, and human-in-the-loop approval workflows.

Khác gì? (Key Differences) Key Differences

• Standard Workflows: Thời gian tối đa 1 năm, lưu vết đầy đủ từng bước, Exactly-once execution.
• Express Workflows: Tối đa 5 phút, khối lượng sự kiện cực lớn (> 100.000/s), chi phí siêu rẻ.

• Standard: Up to 1 year duration, full state execution history, exactly-once execution.
• Express: Up to 5 minutes duration, high-volume streaming (> 100,000/s), cost-optimized.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: Đừng bao giờ để một hàm Lambda gọi trực tiếp một hàm Lambda khác và chờ kết quả (Anti-pattern tốn tiền vô ích)! Phải dùng Step Functions để điều phối chuỗi gọi hàm.

⚠️ Exam Trap: Never chain Lambda functions by having one Lambda invoke and wait for another (costly anti-pattern)! Always use Step Functions to orchestrate distributed workflows.

3. Phân biệt then chốt: Cognito User Pools vs Cognito Identity Pools 3. Critical Distinction: Cognito User Pools vs Cognito Identity Pools
Hiểu rõ ranh giới giữa Xác thực danh tính (Authentication) và Cấp quyền truy cập AWS (Authorization) Grasping the boundary between Authentication (Who you are) and Authorization (What you can access)
🔑 1. Cognito User Pools (CUP) — Authentication (Xác thực) 🔑 1. Cognito User Pools (CUP) — Authentication

• Mục đích: Là một danh bạ người dùng (User Directory) hoàn chỉnh trên đám mây.
• Tính năng: Xử lý đăng ký tài khoản (Sign-up), đăng nhập (Sign-in), quên mật khẩu, xác thực đa yếu tố (MFA), đăng nhập bằng mạng xã hội (Google, Facebook, Apple) hoặc SAML/OIDC của công ty.
• Kết quả trả về: Trả về các chuỗi mã thông báo JSON Web Tokens (JWT) gồm: ID Token, Access Token và Refresh Token.
👉 Người dùng có JWT nhưng chưa có quyền gọi trực tiếp bất kỳ API nào của AWS!

• Purpose: A managed, serverless User Directory.
• Features: Handles sign-up, sign-in, self-service password recovery, Multi-Factor Authentication (MFA), and social/enterprise federated logins (Google, Apple, SAML/OIDC).
• Output: Issues standard JSON Web Tokens (JWT): ID Token, Access Token, and Refresh Token.
👉 Holding a JWT grants zero direct permissions to AWS APIs!

🛡️ 2. Cognito Identity Pools — Authorization (Cấp quyền AWS) 🛡️ 2. Cognito Identity Pools — Authorization

• Mục đích: Đổi các token xác thực (từ Cognito User Pools hoặc Google/Facebook) lấy thông tin xác thực AWS IAM tạm thời (Temporary AWS Credentials).
• Cách hoạt động: Gắn với các IAM Role (Authenticated Role và Unauthenticated/Guest Role).
• Tình huống kinh điển đề thi: Cho phép ứng dụng di động cho khách hàng upload ảnh trực tiếp lên s3://my-bucket/users/{cognito-identity-id}/* mà không cần đi qua máy chủ trung gian → Bắt buộc dùng Cognito Identity Pools.

• Purpose: Exchanges authentication tokens (from User Pools or Social IdPs) for temporary AWS IAM credentials (via AWS STS).
• Mechanics: Associates users with dedicated IAM Roles (Authenticated vs Unauthenticated/Guest).
• Classic Exam Scenario: Enabling mobile users to upload files directly to their personal folder s3://my-bucket/users/{cognito-identity-id}/* without backend proxying → Must choose Cognito Identity Pools.

4. Phân loại 3 phương thức kích hoạt hàm AWS Lambda 4. The 3 Lambda Invocation Models & Error Handling Mechanics
Đồng bộ (Synchronous), Bất đồng bộ (Asynchronous) và Thăm dò nguồn sự kiện (Event Source Mapping) Synchronous, Asynchronous, and Event Source Mapping execution patterns
🔄
Đồng bộ (Synchronous Invocation)
• Dịch vụ kích hoạt: API Gateway, ALB, CloudFront (Lambda@Edge), AWS CLI.
• Phía gọi hàm sẽ chờ đợi Lambda xử lý xong và nhận lại kết quả phản hồi.
• Xử lý lỗi: Bên gọi nhận mã lỗi ngay lập tức (ví dụ: HTTP 429 hoặc 500) và bên gọi tự quyết định việc có thử lại hay không. • Triggers: API Gateway, ALB, CloudFront (Lambda@Edge), AWS CLI.
• The caller waits for the function execution to finish and return a response.
• Error handling: Caller immediately receives status code (HTTP 429/500) and manages its own retry logic.
📬
Bất đồng bộ (Asynchronous Invocation)
• Dịch vụ kích hoạt: Amazon S3, Amazon SNS, Amazon EventBridge, AWS CodeCommit.
• Phía gọi hàm nhận ngay mã HTTP 202 Accepted và không chờ kết quả.
• Xử lý lỗi: Lambda tự động thử lại tối đa 2 lần. Nếu vẫn thất bại → Tự động đẩy sự kiện vào Dead Letter Queue (SQS/SNS) hoặc Lambda Destinations. • Triggers: Amazon S3, Amazon SNS, Amazon EventBridge, AWS CodeCommit.
• The caller receives an immediate HTTP 202 Accepted without waiting.
• Error handling: Lambda automatically retries up to 2 times. Failed payloads route to a DLQ (SQS/SNS) or Lambda Destinations.
📊
Thăm dò nguồn sự kiện (Event Source Mapping)
• Dịch vụ kích hoạt: Amazon Kinesis Data Streams, Amazon DynamoDB Streams, Amazon SQS.
• Dịch vụ Lambda chủ động thăm dò (poll) dữ liệu theo mẻ (batches) từ nguồn rồi mới gọi hàm.
• Với Kinesis/DynamoDB: Xử lý theo từng Shard. Nếu 1 bản ghi bị lỗi → Toàn bộ Shard bị nghẽn trừ khi cấu hình BisectBatchOnFunctionError hoặc Maximum Record Age! • Triggers: Amazon Kinesis Data Streams, Amazon DynamoDB Streams, Amazon SQS.
• Lambda service itself polls records in batches from the stream/queue.
• With Kinesis/DynamoDB: Processed per shard. A failing record blocks the shard unless mitigated via BisectBatchOnFunctionError or Maximum Record Age!
🏆
5. Nguyên tắc vàng ra quyết định kiến trúc Serverless — SAA-C03 5. Golden Architectural Decision Rules: Serverless — SAA-C03
Các quy tắc bất biến giúp chọn đúng giải pháp không máy chủ trong 30 giây Inviolable rules to identify the correct serverless solution in 30 seconds
1
Tác vụ chạy > 15 phút = Không bao giờ chọn Lambda Workloads Exceeding 15 Minutes = Never Choose Lambda
AWS Lambda có giới hạn cứng tuyệt đối là 15 phút (900 giây). Mọi câu hỏi mô tả việc xử lý video hàng giờ, huấn luyện Machine Learning hay batch job lớn → Loại bỏ ngay các đáp án dùng Lambda! Chọn ECS Fargate, AWS Batch hoặc EC2.
AWS Lambda enforces a strict hard ceiling of 15 minutes. Scenarios describing multi-hour video rendering, ML training, or long ETL batch jobs → Instantly eliminate Lambda options! Choose ECS Fargate, AWS Batch, or EC2.
2
Bán gói API Keys / Giới hạn số lượng request = API Gateway REST API Monetizing API Keys / Custom Quota Plans = API Gateway REST API
HTTP API rẻ hơn nhưng không có tính năng Usage Plans và API Keys. Nếu đề bài yêu cầu tạo các gói giới hạn theo khách hàng (ví dụ: gói Basic 100 req/ngày, gói Pro 10.000 req/ngày) → Bắt buộc phải chọn API Gateway REST API.
HTTP API is cheaper but lacks Usage Plans and API Keys. If scenario demands tiered customer limits (e.g. Basic 100 req/day vs Pro 10,000 req/day) → Strictly choose API Gateway REST API.
3
Upload trực tiếp lên S3 từ Client = Cognito Identity Pools Direct Client S3 Uploads = Cognito Identity Pools
Để người dùng đăng nhập bằng mạng xã hội rồi upload file trực tiếp lên S3 mà không cần máy chủ trung gian gánh băng thông → Kết hợp Cognito Identity Pools để cấp quyền IAM tạm thời gắn biến ${cognito-identity.amazonaws.com:sub}.
To let mobile/web users authenticate via social logins and upload directly to private S3 prefixes → Use Cognito Identity Pools granting temporary IAM roles with the ${cognito-identity.amazonaws.com:sub} variable.
4
Điều phối chuỗi nghiệp vụ có xử lý lỗi = AWS Step Functions Multi-Step Business Logic with Retries = AWS Step Functions
Không viết code phức tạp lồng nhau giữa các microservices. Khi cần luồng xử lý phân nhánh, tự động retry, bồi hoàn giao dịch (Saga pattern) hoặc chờ duyệt → Luôn dùng AWS Step Functions State Machine.
Never hand-code brittle cross-service invocations. When orchestrating branching logic, automated exponential backoff, compensation flows (Saga pattern), or human approval → Always use AWS Step Functions.
