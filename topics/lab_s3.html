2. Bài thực hành 2: Tạo S3 Pre-signed URL 2. Hands-On 2: Generating S3 Pre-signed URLs
Tệp nguồn: aws_document/s3-advanced/pre-signed-url.sh Source: aws_document/s3-advanced/pre-signed-url.sh
# 1. Luôn truyền tham số --region chính xác của bucket: aws s3 presign s3://mybucket/myobject --region my-region # 2. Tùy chỉnh thời gian hết hạn (tính bằng giây, mặc định 3600s = 1 giờ): aws s3 presign s3://mybucket/myobject --expires-in 300 --region my-region # 3. Nếu gặp lỗi chữ ký khi tạo URL cho file mã hóa (SSE-KMS), bật s3v4: aws configure set default.s3.signature_version s3v4
Giải thích & Ứng dụng thực tế
• Mục đích: Cấp quyền tải xuống (GET) hoặc tải lên (PUT) tạm thời một tệp Private trên S3 mà không cần mở Public Bucket.
• Quyền hạn: Người nhận Pre-signed URL sẽ kế thừa đúng quyền đọc/ghi của IAM User hoặc IAM Role đã sinh ra URL đó.
• Khắc phục lỗi: Lệnh aws configure set default.s3.signature_version s3v4 bắt buộc dùng chuẩn ký Signature Version 4 để tránh lỗi từ chối truy cập với các Region mới hoặc đối tượng mã hóa KMS.
• Purpose: Grant temporary GET or PUT access to a private S3 object without making the bucket public.
• Permissions: The URL inherits the permissions of the IAM principal that generated it.
• Troubleshooting: Setting default.s3.signature_version s3v4 enforces Signature Version 4, preventing signature mismatch errors on newer regions or KMS-encrypted objects.

3. Bài thực hành 3: Bật/Tắt S3 MFA Delete 3. Hands-On 3: Enabling/Disabling S3 MFA Delete
Tệp nguồn: aws_document/s3-advanced/mfa-delete.sh Source: aws_document/s3-advanced/mfa-delete.sh
# 1. Cấu hình profile CLI bằng Access Key của Root User: aws configure --profile root-mfa-delete-demo # 2. Bật MFA Delete (Phải kèm ARN thiết bị MFA và mã 6 số hiện tại): aws s3api put-bucket-versioning --bucket mfa-demo-stephane \ --versioning-configuration Status=Enabled,MFADelete=Enabled \ --mfa "arn-of-mfa-device mfa-code" --profile root-mfa-delete-demo # 3. Tắt MFA Delete và XÓA NGAY Root Access Keys trong IAM Console! aws s3api put-bucket-versioning --bucket mfa-demo-stephane \ --versioning-configuration Status=Enabled,MFADelete=Disabled \ --mfa "arn-of-mfa-device mfa-code" --profile root-mfa-delete-demo
3 Quy tắc bắt buộc của MFA Delete trong đề thi
1. Chỉ có Root Account mới được phép bật/tắt MFA Delete và chỉ thực hiện được qua AWS CLI / API (không thể bật trên giao diện Web Console).
2. Bucket bắt buộc phải bật Versioning.
3. Khi bật, MFA chỉ yêu cầu khi Xóa vĩnh viễn một Object Version (Delete Version) hoặc Tạm dừng Versioning (Suspend Versioning); xóa thường (tạo Delete Marker) KHÔNG cần MFA.
1. Only the Root Account can enable/disable MFA Delete, and ONLY via AWS CLI / API (not supported in the Management Console UI).
2. Bucket Versioning must be enabled.
3. MFA is required ONLY to permanently delete an object version or suspend versioning; simple deletes (creating a Delete Marker) do NOT require MFA.

4. Bài thực hành 4: Truy vấn S3 Server Access Logs bằng SQL trên Amazon Athena 4. Hands-On 4: Querying S3 Server Access Logs with SQL in Amazon Athena
Tệp nguồn: aws_document/s3-advanced/athena-s3-access-logs.sql Source file: aws_document/s3-advanced/athena-s3-access-logs.sql
Mã nguồn SQL trong aws_document/s3-advanced/athena-s3-access-logs.sql SQL Script in aws_document/s3-advanced/athena-s3-access-logs.sql
create database s3_access_logs_db; CREATE EXTERNAL TABLE IF NOT EXISTS s3_access_logs_db.mybucket_logs( BucketOwner STRING, Bucket STRING, RequestDateTime STRING, RemoteIP STRING, Requester STRING, RequestID STRING, Operation STRING, Key STRING, RequestURI_operation STRING, RequestURI_key STRING, RequestURI_httpProtoversion STRING, HTTPstatus STRING, ErrorCode STRING, BytesSent BIGINT, ObjectSize BIGINT, TotalTime STRING, TurnAroundTime STRING, Referrer STRING, UserAgent STRING, VersionId STRING, HostId STRING, SigV STRING, CipherSuite STRING, AuthType STRING, EndPoint STRING, TLSVersion STRING ) ROW FORMAT SERDE 'org.apache.hadoop.hive.serde2.RegexSerDe' WITH SERDEPROPERTIES ( 'serialization.format' = '1', 'input.regex' = '([^ ]*) ([^ ]*) \\[(.*?)\\] ([^ ]*) ([^ ]*) ([^ ]*) ([^ ]*) ([^ ]*) \\\"([^ ]*) ([^ ]*) (- |[^ ]*)\\\" (-|[0-9]*) ([^ ]*) ([^ ]*) ([^ ]*) ([^ ]*) ([^ ]*) ([^ ]*) (\"[^\"]*\") ([^ ]*)(?: ([^ ]*) ([^ ]*) ([^ ]*) ([^ ]*) ([^ ]*) ([^ ]*))?.*$' ) LOCATION 's3://target-bucket-name/prefix/'; -- Truy vấn 1: Thống kê số lượng request theo loại thao tác và mã HTTP Status SELECT requesturi_operation, httpstatus, count(*) FROM "s3_access_logs_db"."mybucket_logs" GROUP BY requesturi_operation, httpstatus; -- Truy vấn 2: Tìm tất cả các truy cập bị từ chối quyền (HTTP 403 Forbidden) SELECT * FROM "s3_access_logs_db"."mybucket_logs" WHERE httpstatus='403';
Các bước thực hiện trên Athena Console
1. Bật Server access logging trên S3 Bucket nguồn và trỏ đích lưu sang một Target Logging Bucket riêng biệt (tuyệt đối không trỏ vào chính bucket nguồn để tránh vòng lặp vô hạn!).
2. Mở Amazon Athena, cấu hình Query result location sang một bucket lưu kết quả.
3. Thay s3://target-bucket-name/prefix/ bằng đường dẫn chứa log thực tế, chạy lệnh CREATE EXTERNAL TABLE rồi chạy 2 câu lệnh SELECT để kiểm toán bảo mật.
1. Enable Server access logging on your source S3 bucket and specify a separate Target Logging Bucket (never log to the same bucket to avoid an infinite logging loop!).
2. Open Amazon Athena and set up a Query result location S3 bucket.
3. Replace s3://target-bucket-name/prefix/ with your log bucket path, execute CREATE EXTERNAL TABLE, and run the SELECT queries for security auditing.
Tại sao dùng Athena (Serverless SQL)?
• Amazon Athena sử dụng engine Presto/Trino kèm bộ phân tích RegexSerDe để đọc trực tiếp các tệp log văn bản thô trên S3 mà không cần dựng cơ sở dữ liệu hay ETL.
• Trong đề thi SAA-C03, khi gặp yêu cầu "phân tích S3 Access Logs / VPC Flow Logs / CloudTrail Logs đột xuất (ad-hoc) bằng SQL với chi phí vận hành thấp nhất (Serverless)" → Đáp án luôn là Amazon Athena!
• Amazon Athena uses Presto/Trino with RegexSerDe to parse raw S3 text logs directly in-place without provisioning databases or ETL pipelines.
• In SAA-C03, whenever a scenario asks for "serverless ad-hoc SQL analysis directly on S3 Access Logs, VPC Flow Logs, or CloudTrail logs" → the answer is always Amazon Athena!
