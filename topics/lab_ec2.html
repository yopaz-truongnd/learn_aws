2. Bài thực hành 1: Tự động cài Web Server với EC2 User Data 2. Hands-On 1: Automated Web Server Bootstrapping with EC2 User Data
Tệp nguồn: aws_document/ec2-fundamentals/ec2-user-data.sh Source file: aws_document/ec2-fundamentals/ec2-user-data.sh
Mã nguồn trong aws_document/ec2-fundamentals/ec2-user-data.sh Source code in aws_document/ec2-fundamentals/ec2-user-data.sh
#!/bin/bash # Use this for your user data (script from top to bottom) # install httpd (Linux 2 version) yum update -y yum install -y httpd systemctl start httpd systemctl enable httpd echo "<h1>Hello World from $(hostname -f)</h1>" > /var/www/html/index.html
Giải thích chi tiết từng câu lệnh Line-by-Line Explanation
#!/bin/bash & Quyền thực thi Root
Dòng Shebang khai báo trình thông dịch Bash shell. Mọi lệnh trong EC2 User Data mặc định được dịch vụ cloud-init chạy tự động dưới quyền root, do đó bạn không cần gõ sudo ở đầu lệnh.
The Shebang line declares the Bash shell interpreter. All commands in EC2 User Data are executed automatically by cloud-init as the root user, so sudo is not required.
yum update -y & yum install -y httpd
Cập nhật toàn bộ gói hệ điều hành và cài đặt gói Apache HTTP Server (httpd). Cờ -y cực kỳ quan trọng trong script tự động vì nó tự động trả lời "Yes" cho mọi câu hỏi xác nhận (nếu thiếu -y, script sẽ bị treo chờ người dùng bấm phím).
Updates OS packages and installs the Apache HTTP Server (httpd). The -y flag is mandatory in non-interactive scripts to auto-confirm prompts without hanging.
systemctl start & systemctl enable httpd
systemctl start httpd bật dịch vụ web ngay lập tức. systemctl enable httpd đăng ký Apache tự khởi động cùng hệ điều hành nếu sau này máy chủ EC2 bị Reboot hoặc Stop/Start.
systemctl start httpd starts the web server immediately. systemctl enable httpd configures Apache to start automatically across future OS reboots.
$(hostname -f) → /var/www/html/index.html
Lệnh hostname -f lấy tên miền nội bộ đầy đủ (FQDN, ví dụ ip-172-31-20-15.ec2.internal) của máy chủ và ghi đè vào tệp trang chủ mặc định của Apache. Rất hữu ích khi đứng sau Load Balancer để biết máy chủ nào đang phản hồi!
hostname -f retrieves the instance's Fully Qualified Domain Name (e.g., ip-172-31-20-15.ec2.internal) and writes it to Apache's default web root. Great for verifying Load Balancer distribution!

Wait for the instance state to reach Running (allow 30-60 seconds for httpd installation). Copy the Public IPv4 address and visit http://<Public-IP> (do NOT use https:// since only port 80 is open). You will see "Hello World from ip-...".

🛠️ Các bước thực hiện 🛠️ Execution Steps
Bước 1: Kết nối vào EC2 InstanceStep 1: Connect to EC2 Instance Chọn EC2 instance vừa tạo → nhấn Connect → chọn tab EC2 Instance Connect để mở cửa sổ terminal trực tiếp trên trình duyệt (hoặc SSH từ máy cá nhân). Select your running EC2 instance → click Connect → choose EC2 Instance Connect to open an in-browser terminal (or SSH from your local terminal).
Bước 2: Kiểm tra IMDSv1 vs IMDSv2Step 2: Test IMDSv1 vs IMDSv2 Nếu bạn bật tùy chọn Metadata version: V1 and V2 (token optional), lệnh curl http://169.254.169.254/latest/meta-data/instance-id sẽ trả về ngay mã i-xxxx. Nếu để V2 only (token required), lệnh trên sẽ trả về lỗi 401 Unauthorized và bạn bắt buộc phải xin TOKEN bằng lệnh PUT trước. If V1 and V2 (token optional) is enabled, curl http://169.254.169.254/latest/meta-data/instance-id immediately returns i-xxxx. If V2 only (token required) is set, it returns 401 Unauthorized unless you first obtain a session TOKEN via PUT.
Bước 3: Khám phá cây thư mục MetadataStep 3: Explore the Metadata Tree Thử truy vấn thêm: .../meta-data/public-ipv4, .../meta-data/placement/availability-zone, hoặc .../meta-data/iam/security-credentials/ để xem cách AWS cấp phát STS Token tạm thời cho IAM Role gắn trên EC2. Try querying .../meta-data/public-ipv4, .../meta-data/placement/availability-zone, or .../meta-data/iam/security-credentials/ to see how AWS delivers temporary STS credentials to an attached IAM Role.
🎯 Kiến thức trọng tâm thi SAA-C03 🎯 Key SAA-C03 Exam Takeaways
Địa chỉ IP 169.254.169.254 là gì?What is 169.254.169.254? Đây là địa chỉ Link-local IP cố định chỉ truy cập được từ bên trong chính máy chủ EC2 đó, hoàn toàn không cần kết nối Internet hay NAT Gateway, và không tốn phí truyền dữ liệu. A fixed Link-local IP accessible exclusively from within the EC2 instance itself, requiring no Internet or NAT Gateway connectivity and incurring zero data transfer cost.
Phân biệt Metadata vs User DataMetadata vs User Data • Metadata (/latest/meta-data/): Thông tin về bản thân máy chủ EC2 (Instance ID, IP, AZ, Security Group, IAM Role).
• User Data (/latest/user-data): Đoạn script khởi động mà bạn đã truyền vào khi Launch instance. • Metadata (/latest/meta-data/): Attributes about the EC2 instance (Instance ID, IP, AZ, SG, IAM Role).
• User Data (/latest/user-data): The bootstrap script you supplied at launch time.
Gỡ lỗi khi User Data không chạyDebugging User Data Failures Nếu web server không lên, hãy SSH vào máy và kiểm tra file log tại /var/log/cloud-init-output.log để xem chi tiết lỗi của từng dòng lệnh trong User Data. If the web server fails to start, SSH into the instance and inspect /var/log/cloud-init-output.log to see the exact stdout/stderr of your User Data script.
