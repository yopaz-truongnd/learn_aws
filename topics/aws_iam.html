Permissions boundary
Giới hạn quyền tối đa của một User hoặc Role. Quyền hiệu lực là phần giao với Identity policy.
Sets maximum allowable permissions for a User or Role. Effective permissions equal the intersection with Identity policy.
Phạm vi của SCP SCP Scope & Guardrails
Không áp dụng cho management account. SCP không cấp quyền, chỉ thu hẹp quyền.
Does not apply to the Management Account. SCPs never grant permissions, only restrict boundaries.
Cross-account + resource policy
Cùng account: chỉ cần Allow ở một phía. Khác account: cần Allow ở cả hai phía (Identity policy + Resource policy).
Same account: Allow on one side suffices. Cross-account: Allow required on BOTH sides (Identity policy + Resource policy).
IAM Identity Center
SSO tập trung cho nhiều account trong Organizations, thay cho việc tạo IAM Users rải rác.
Centralized Single Sign-On (SSO) across AWS Organizations, replacing sprawling IAM Users across accounts.
Access Advisor
Cấp user: dịch vụ nào được dùng lần cuối khi nào, để thu hẹp quyền theo Least Privilege.
User-level visibility into service last-accessed timestamps, enabling least-privilege permission pruning.
IAM là dịch vụ Global IAM is a Global Service
Không gắn với Region; Users, Groups, Roles và Policies dùng được ở mọi Region trên toàn cầu.
Not tied to any AWS Region; Users, Groups, Roles, and Policies apply globally across all Regions.

5. Nguyên tắc vàng — SAA-C03 5. Golden Rules — SAA-C03
Ghi nhớ 4 nguyên tắc cốt lõi 4 core architectural rules to memorize
  • 1
    Least Privilege Chỉ cấp đúng và đủ quyền cần thiết để hoàn thành công việc. Grant only the minimum permissions necessary to perform the specified job.
  • 2
    EC2 Instance Profiles: dùng IAM Role, không nhúng Access Key EC2 Instance Profiles: Use IAM Roles, Never Hardcode Access Keys Luôn gán IAM Role cho EC2 / Lambda thay vì hardcode Access Key vào server. Always attach IAM Roles to EC2 / Lambda instances instead of storing static Access Keys on disk or source code.
  • 3
    Cross-Account: IAM Role + STS AssumeRole Ưu tiên Role thay vì tạo IAM User trùng lặp ở tài khoản khác. Prefer assuming IAM Roles via STS over maintaining redundant IAM Users across different accounts.
  • !
    Explicit Deny luôn chiến thắng Explicit Deny Always Wins Dù có bao nhiêu Allow, chỉ cần 1 Deny là request bị chặn ngay lập tức. No matter how many Allows exist, a single Explicit Deny anywhere immediately rejects the request.
