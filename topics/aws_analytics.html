Tối ưu chi phí bằng cách đổi sang định dạng cột (Parquet / ORC) và phân vùng dữ liệu (Partitioning).
• AWS Glue = Serverless ETL & Data Catalog: Glue Crawler tự động quét S3/RDS, suy diễn cấu trúc bảng và cập nhật vào Glue Data Catalog để Athena và Redshift đọc.
• EMR Task Nodes = Luôn chọn EC2 Spot Instances: Cụm EMR gồm Master (quản lý), Core (chạy task + lưu HDFS - không dùng Spot), Task Nodes (chỉ tính toán, không lưu HDFS → dùng Spot tiết kiệm 90%).
• Amazon Redshift = Kho dữ liệu OLAP quy mô Petabyte: Lưu trữ dạng cột (Columnar), xử lý song song MPP. Dùng Redshift Spectrum để truy vấn dữ liệu trực tiếp trong S3 mà không cần nạp vào bảng.
• Amazon QuickSight = BI Dashboard & Trực quan hóa: Tích hợp sẵn bộ nhớ đệm tính toán siêu tốc SPICE Engine, hỗ trợ truy vấn ngôn ngữ tự nhiên (QuickSight Q).
• Amazon OpenSearch = Phân tích log & Tìm kiếm toàn văn: Thay thế Elasticsearch, chuyên gia phân tích log hệ thống từ CloudWatch, VPC Flow Logs và tạo Dashboard trên OpenSearch Dashboards (Kibana). • Amazon Athena = Serverless SQL directly on S3: Billed at $5 per TB scanned. Drastically cut costs by converting files to columnar formats (Parquet / ORC) and partitioning data.
• AWS Glue = Serverless ETL & Data Catalog: Glue Crawlers scan S3/RDS, automatically infer schemas, and store metadata in the Glue Data Catalog for Athena/Redshift.
• EMR Task Nodes = Always leverage EC2 Spot Instances: EMR comprises Master (orchestrator), Core (tasks + HDFS data - avoid Spot), and Task Nodes (pure compute, zero HDFS → ideal for Spot saving 90%).
• Amazon Redshift = Petabyte OLAP Data Warehouse: Columnar storage, Massively Parallel Processing (MPP). Use Redshift Spectrum to query exabytes of S3 data without loading.
• Amazon QuickSight = Serverless BI & Visualizations: Powered by the in-memory SPICE Engine, featuring natural language queries (QuickSight Q).
• Amazon OpenSearch = Log Analytics & Full-Text Search: Managed Elasticsearch replacement for real-time log analysis and OpenSearch Dashboards (Kibana).

🔍 1. Amazon Athena 🔍 1. Amazon Athena
Là gì? (Definition) What is it?

Dịch vụ truy vấn tương tác không máy chủ (Serverless Interactive Query Service) sử dụng ngôn ngữ SQL chuẩn (Presto/Trino) để phân tích dữ liệu trực tiếp trong Amazon S3.

Serverless interactive query service analyzing data directly in Amazon S3 using standard SQL (built on Presto/Trino) with zero database infrastructure.

Dùng khi nào? (When to use) When to use?

Truy vấn khám phá dữ liệu đột xuất (Ad-hoc queries), phân tích nhật ký mạng VPC Flow Logs, CloudTrail, ALB Access Logs hoặc dữ liệu phân tích kinh doanh lưu trữ trong hồ dữ liệu S3 Data Lake.

Ad-hoc analytical queries, security investigations into VPC Flow Logs, CloudTrail, and ALB logs, or querying raw data in an S3 Data Lake.

Khác gì? (Key Differences) Key Differences

Không cần nạp (load) dữ liệu vào database trước! Chi phí tính theo $5 / TB dữ liệu quét. Không tốn bất kỳ chi phí duy trì cụm máy chủ nào khi không chạy câu truy vấn.

Zero data loading required! Pay-per-query model at $5 per TB scanned. Completely cost-free when queries are idle.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: Để tối ưu chi phí và tăng tốc độ Athena → Chuyển đổi file sang dạng cột Apache Parquet hoặc ORC và phân vùng (Partitioning) theo thư mục /year/month/day/.

⚠️ Exam Trap: To optimize Athena query costs and speed → Convert datasets to columnar Apache Parquet / ORC and partition S3 paths by /year/month/day/.

🧩 2. AWS Glue 🧩 2. AWS Glue
Là gì? (Definition) What is it?

Dịch vụ trích xuất, biến đổi và nạp dữ liệu (ETL) không máy chủ, tích hợp kho siêu dữ liệu tập trung Glue Data Catalog.

Fully managed serverless Extract, Transform, and Load (ETL) service featuring a centralized metadata repository called the Glue Data Catalog.

Dùng khi nào? (When to use) When to use?

Tự động phát hiện cấu trúc dữ liệu (Schema Discovery) qua Glue Crawlers, chuẩn hóa/làm sạch dữ liệu và chuyển đổi định dạng (JSON/CSV → Parquet) trong đường ống dữ liệu tự động.

Automated schema discovery via Glue Crawlers, data sanitization/enrichment, and batch format conversions (CSV → Parquet) across data pipelines.

Khác gì? (Key Differences) Key Differences

Serverless chạy trên nền tảng Apache Spark mà bạn không cần quản lý máy chủ. Glue Data Catalog được chia sẻ chung cho Athena, EMR và Redshift Spectrum để đọc cùng một schema.

Serverless Apache Spark execution without cluster administration. The Glue Data Catalog acts as a unified central schema registry shared across Athena, EMR, and Redshift.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: Đề bài nhắc đến: "tự động quét S3 để cập nhật schema bảng" → Chọn Glue Crawler. "Chuẩn bị dữ liệu trực quan không cần viết code" → Chọn Glue DataBrew.

⚠️ Exam Trap: Scenarios citing "automatically scan S3 to update table schemas" → Choose Glue Crawler. "Visual data preparation without code" → Choose Glue DataBrew.

🏛️ 3. Amazon Redshift 🏛️ 3. Amazon Redshift
Là gì? (Definition) What is it?

Kho dữ liệu đám mây quy mô Petabyte (OLAP Data Warehouse) xử lý song song khối lượng lớn (MPP) và tối ưu hóa lưu trữ theo cột (Columnar Storage).

Petabyte-scale cloud data warehouse optimized for Online Analytical Processing (OLAP) leveraging Massively Parallel Processing (MPP) and columnar data layout.

Dùng khi nào? (When to use) When to use?

Báo cáo kinh doanh doanh nghiệp định kỳ, kết hợp dữ liệu từ nhiều nguồn khác nhau vào một kho duy nhất để chạy các câu truy vấn tổng hợp phức tạp (SUM, AVG, GROUP BY trên hàng tỷ dòng).

Enterprise-wide analytical reporting consolidating multi-source transactional data into a single source of truth executing complex multi-billion-row aggregations.

Khác gì? (Key Differences) Key Differences

Khác với RDS (chuyên xử lý giao dịch OLTP theo từng dòng), Redshift chuyên đọc các cột cụ thể. Tính năng Redshift Spectrum cho phép mở rộng truy vấn trực tiếp vào S3 mà không cần nạp dữ liệu.

Unlike transactional row-based RDS (OLTP), Redshift compresses and reads specific columns. Redshift Spectrum extends SQL queries directly into S3 without ingestion.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: Redshift không phù hợp cho OLTP (thêm/sửa từng bản ghi lẻ tẻ). Nếu cần nạp dữ liệu lớn vào Redshift với tốc độ cao nhất → Luôn dùng lệnh COPY từ Amazon S3.

⚠️ Exam Trap: Redshift is ill-suited for OLTP (single-row inserts/updates). To bulk load massive data into Redshift with maximum throughput → Always use the S3 COPY command.

3. Kiến trúc 3 loại Node trong cụm Amazon EMR 3. Node Roles in an Amazon EMR Cluster: Master, Core, and Task Nodes
Chiến thuật kết hợp On-Demand và Spot Instances để giảm tới 90% chi phí xử lý Big Data Combining On-Demand and Spot Instances to optimize big data processing costs up to 90%
👑
1. Master Node (Nút điều phối trung tâm)
• Quản lý toàn bộ cụm, phân phối tác vụ YARN và theo dõi trạng thái các node khác.
• Khuyến nghị: Luôn dùng On-Demand hoặc Reserved Instance. Tuyệt đối không dùng Spot Instance cho Master Node vì nếu Master bị thu hồi, toàn bộ cụm sẽ chết!
• Hỗ trợ cấu hình Multi-Master (3 node) để đạt High Availability (HA). • Manages the cluster, coordinates YARN tasks, tracks health.
• Recommendation: Always run on On-Demand or Reserved Instances. Never use Spot for Master Node because termination kills the cluster!
• Multi-Master (3 nodes) supported for HA.
💾
2. Core Node (Nút chạy tác vụ & Lưu dữ liệu HDFS)
• Vừa thực thi tác vụ tính toán, vừa lưu trữ dữ liệu trên hệ thống tệp phân tán Hadoop (HDFS).
• Khuyến nghị: Dùng On-Demand. Nếu dùng Spot, khi bị thu hồi đột ngột có thể làm mất dữ liệu HDFS phân tán chưa kịp sao lưu. • Executes tasks and stores persistent data on Hadoop Distributed File System (HDFS).
• Recommendation: Standard On-Demand Instances. Spot instances risk HDFS data loss upon reclamation.
⚡
3. Task Node (Nút thuần tính toán — Pure Compute)
• Chỉ chạy các tác vụ tính toán Spark/Hadoop, hoàn toàn không lưu dữ liệu HDFS.
• Nếu một Task Node bị ngắt kết nối đột ngột → Không bị mất dữ liệu, tác vụ chỉ cần chạy lại trên node khác.
• 👉 Bẫy đề thi kinh điển: Luôn sử dụng EC2 Spot Instances cho Task Nodes để tối đa hóa hiệu năng với chi phí rẻ nhất! • Executes computation tasks only, storing zero HDFS data.
• If a Task Node terminates abruptly → Zero data loss; task simply reschedules.
• 👉 Classic Exam Rule: Always deploy EC2 Spot Instances for Task Nodes to slash processing costs!

4. Nguyên tắc vàng ra quyết định kiến trúc Analytics — SAA-C03 4. Golden Architectural Decision Rules: Analytics — SAA-C03
Các quy tắc bất biến giúp loại trừ ngay phương án sai trong 30 giây Inviolable rules to identify the correct analytics architecture in 30 seconds
1
Truy vấn SQL trực tiếp file S3 không dựng DB = Amazon Athena Direct Serverless SQL on S3 Files = Amazon Athena
Bất cứ khi nào đề thi nhắc đến: "phân tích log VPC Flow Logs / CloudTrail / ALB Access Logs lưu trong S3 bằng SQL mà không muốn quản lý máy chủ" → Đáp án luôn là Amazon Athena.
Whenever a scenario mentions: "query VPC Flow Logs / CloudTrail / ALB access logs in S3 using SQL without provisioning databases or servers" → The answer is always Amazon Athena.
2
Tối ưu chi phí Athena = Apache Parquet + Phân vùng (Partitioning) Athena Cost Optimization = Columnar Parquet + Partitioning
Athena tính phí trên dung lượng dữ liệu quét. Chuyển đổi định dạng tệp từ CSV/JSON sang Parquet / ORC và phân vùng theo đường dẫn thư mục S3 giúp giảm tới 90% dữ liệu quét và giảm 90% hóa đơn.
Athena bills per byte scanned. Converting CSV/JSON to columnar Parquet / ORC and partitioning S3 prefixes reduces scanned data and costs by up to 90%.
3
Truy vấn dữ liệu S3 từ Redshift = Redshift Spectrum Querying External S3 Data from Redshift = Redshift Spectrum
Nếu công ty đã có sẵn kho dữ liệu Amazon Redshift và muốn truy vấn hàng Petabyte dữ liệu lịch sử lưu trong S3 mà không cần nạp vào ổ đĩa của cụm → Chọn Redshift Spectrum.
When an existing Amazon Redshift warehouse must query petabytes of cold historical data sitting in S3 without loading it into Redshift storage → Choose Redshift Spectrum.
4
Dashboard BI & Trực quan hóa Serverless = Amazon QuickSight Serverless Business Intelligence Dashboards = Amazon QuickSight
Khi cần xây dựng dashboard trực quan cho người dùng doanh nghiệp, tự co giãn không máy chủ và tích hợp bộ nhớ đệm SPICE → Chọn ngay Amazon QuickSight.
When delivering visual interactive business dashboards serverlessly with high-speed in-memory SPICE caching → Always select Amazon QuickSight.
