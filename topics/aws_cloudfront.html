1. Nền tảng mạng biên toàn cầu (Edge Networking Architecture) 1. Global Edge Networking Architecture
So sánh cơ chế tăng tốc nội dung qua mạng lưới hơn 400 điểm Edge Locations của AWS Content and network acceleration mechanics powered by 400+ AWS Edge Locations
Amazon CloudFront (Mạng phân phối nội dung CDN)
Mạng lưới phân phối nội dung CDN toàn cầu hoạt động tại Layer 7 (HTTP/HTTPS). Có lưu đệm (Caching) nội dung tĩnh và động tại các trạm Edge Locations gần người dùng nhất. Giúp giảm độ trễ tải trang web, giải tỏa tải cho máy chủ gốc (Origin) và bảo vệ chống tấn công DDoS.
CDN Layer 7Edge CachingWebsites, Video Streaming
Global Content Delivery Network (CDN) operating at Layer 7 (HTTP/HTTPS). Caches content at edge points of presence (PoPs) closest to clients. Minimizes download latency, shields origins from traffic surges, and protects against DDoS attacks.
CDN Layer 7Edge CachingWebsites, Media Streaming
AWS Global Accelerator (Tăng tốc mạng Anycast)
Dịch vụ tối ưu đường truyền mạng hoạt động tại Layer 4 (TCP/UDP). Cung cấp 2 địa chỉ Anycast Static IPv4 cố định. KHÔNG LƯU ĐỆM (No Caching). Dẫn luồng truy cập của client vào mạng cáp quang nội bộ tốc độ cao của AWS ngay tại Edge Location gần nhất, tránh tình trạng tắc nghẽn của Internet công cộng.
Network Layer 42 Anycast Static IPsGaming, IoT, VoIP, Non-HTTP
Networking service operating at Layer 4 (TCP/UDP). Provides 2 static Anycast IPv4 addresses. ZERO CACHING. Routes client traffic onto AWS's private global fiber network backbone at the nearest edge PoP, bypassing public Internet congestion.
Network Layer 42 Anycast Static IPsGaming, IoT, VoIP, Non-HTTP
S3 Transfer Acceleration (So sánh đối chiếu)
Chuyên biệt duy nhất cho việc tăng tốc độ tải tệp LÊN (Upload) Amazon S3 qua khoảng cách địa lý xa. Dữ liệu đi vào Edge Location của CloudFront rồi truyền về bucket qua đường truyền riêng của AWS. Chỉ dùng cho S3, không dùng cho web server hay API.
Designed exclusively to accelerate uploads directly into Amazon S3 across long geographic distances. Ingests data at CloudFront edge locations and tunnels it over AWS private backbone to target bucket. Exclusively for S3.
Hệ thống Regional Edge Caches (REC)
Các cụm bộ nhớ đệm khu vực quy mô lớn đặt giữa Edge Locations và máy chủ Origin. Khi nội dung tại Edge Location bị hết hạn (Cache Miss), nó sẽ hỏi Regional Edge Cache trước. Giúp giảm thiểu tối đa các yêu cầu phải chạy về Origin server ở xa.
Larger caching hubs positioned between edge PoPs and customer origin servers. When an edge location experiences a cache miss, it checks the Regional Edge Cache before reaching all the way back to the origin, conserving backend bandwidth.

🔑 Signed URLs vs Signed Cookies 🔑 Signed URLs vs Signed Cookies
Phân biệt khi cấp quyền nội dung có phí (Premium Content) • Signed URL: Dùng để cấp quyền truy cập vào MỘT tệp tin riêng lẻ duy nhất (ví dụ: link tải 1 khóa học hoặc 1 bài hát sau khi thanh toán).

• Signed Cookie: Grants access to MULTIPLE files or directory trees (e.g. authenticated subscribers streaming a catalog of premium videos without changing URL paths).
⚡ Caching Mechanics & Invalidation ⚡ Caching & Invalidation
Xóa đệm (Invalidation) vs Versioning • Khi bạn cập nhật file trên máy chủ gốc nhưng CloudFront vẫn trả về file cũ trong bộ nhớ đệm, bạn cần chạy lệnh CloudFront Invalidation (ví dụ: xóa /* hoặc /images/*).
• Nhược điểm: Chạy Invalidation nhiều sẽ bị tính phí.
• Giải pháp tối ưu nhất: Đặt tên tệp theo số phiên bản (ví dụ: style_v2.css). • When updating origin files that remain cached at the edge, execute a CloudFront Invalidation (e.g. /* or /assets/*).
• Trade-off: Invalidation requests incur costs beyond the free monthly tier.
• Optimal Pattern: Version filenames directly (e.g. style_v2.css).

5. Các bẫy & Kịch bản đề thi thường gặp (SAA-C03 Exam Traps) 5. Common Exam Traps & Scenarios (SAA-C03)
Những tình huống phân biệt kinh điển giữa các giải pháp mạng biên toàn cầu Canonical situational questions testing edge networking solutions
Khách hàng yêu cầu Cố định 2 IP tĩnh cho ứng dụng toàn cầu
• Đề bài: "Ứng dụng phân tán trên 2 Region, yêu cầu người dùng toàn cầu kết nối vào hệ thống thông qua đúng 2 địa chỉ IP tĩnh để cấu hình mở tường lửa (Firewall Whitelisting). Đồng thời hệ thống phải tự động chuyển thảm họa dưới 1 phút nếu 1 Region sập".
• Bẫy: Chọn CloudFront là SAI (CloudFront không có 2 IP tĩnh).
• Đáp án chuẩn: AWS Global Accelerator (Cung cấp 2 Anycast Static IPs cố định và chuyển thảm họa tự động < 1 phút).
• Scenario: Multi-region app requires global clients to connect via exactly 2 static IP addresses for corporate firewall whitelisting, with automated failover under 1 minute.
• Trap: CloudFront is INVALID (CloudFront does not provide static IPs).
• Canonical Answer: AWS Global Accelerator (Provides 2 Anycast static IPs and automated sub-minute failover).
CloudFront Signed URL vs S3 Presigned URL
• Khi nào dùng cái nào?
• S3 Presigned URL: Client tải trực tiếp từ S3 Bucket (bỏ qua CDN). Thường dùng khi tải lên (Upload) trực tiếp hoặc khi dữ liệu phân tán không cần cache.
• CloudFront Signed URL: Client tải thông qua mạng lưới Edge Caching của CloudFront. Bắt buộc dùng khi nội dung có lưu đệm tại biên hoặc khi muốn tận dụng tính năng giới hạn IP/thời gian của CloudFront.
• Choosing between Signed URLs:
• S3 Presigned URL: Client fetches directly from S3 (bypassing CDN). Common for direct uploads or private non-cached data.
• CloudFront Signed URL: Client fetches via CloudFront edge caches. Mandatory when content is cached at the edge or requiring CloudFront IP restrictions.
Bảo vệ máy chủ Origin ALB phía sau CloudFront
• Vấn đề: Làm sao ngăn người dùng vượt mặt (bypass) CloudFront để truy cập thẳng vào Application Load Balancer?
• Giải pháp chuẩn:
  1. Cấu hình CloudFront gửi thêm một Custom HTTP Header bí mật (ví dụ: X-Custom-Secret: abc123xyz) trong mỗi request gửi về ALB.
  2. Cấu hình Listener Rule trên ALB: Chỉ chuyển tiếp request nếu có chứa header bí mật này, còn lại thì trả về HTTP 403 Forbidden!
• Problem: How to prevent users from bypassing CloudFront and hitting the backend Application Load Balancer directly?
• Canonical Solution:
  1. Configure CloudFront to inject a secret Custom HTTP Header (e.g. X-Custom-Secret) on requests to the origin.
  2. Configure ALB Listener Rules to forward traffic strictly when the secret header matches; return 403 Forbidden otherwise!
Geo-Restriction (Chặn theo vị trí địa lý)
• Cho phép thiết lập Whitelist (Chỉ cho phép một số quốc gia) hoặc Blacklist (Chặn một số quốc gia).
• Phù hợp với các yêu cầu kiểm soát bản quyền bản địa hóa (ví dụ: chỉ phát sóng trực tiếp trận bóng đá cho người xem ở Việt Nam).
• Nếu cần kiểm soát chi tiết hơn (chặn theo thành phố, user-agent, chống giả mạo IP), kết hợp thêm AWS WAF.
• Configure Allowlist (permit selected countries) or Blocklist (deny selected countries) at the edge.
• Common for broadcasting licensing compliance (e.g. streaming sports strictly within authorized territories).
• For advanced filtering (city-level, anti-spoofing, custom rules), integrate with AWS WAF.

6. Nguyên tắc vàng khi làm bài thi (SAA-C03 Edge Golden Rules) 6. SAA-C03 Edge Networking Golden Rules
Quy tắc loại trừ đáp án siêu tốc cho phần mạng biên và tăng tốc toàn cầu Essential axioms to rapidly eliminate incorrect choices in edge questions
  • 1
    Cần Caching nội dung web tại biên → LUÔN CHỌN AMAZON CLOUDFRONT Edge Caching required → ALWAYS CHOOSE AMAZON CLOUDFRONT Khi đề bài nhắc đến việc lưu đệm hình ảnh, video, mã nguồn web tại các điểm biên toàn cầu để giảm tải máy chủ gốc, CloudFront luôn là lựa chọn chính xác. Global Accelerator hoàn toàn KHÔNG CÓ chức năng Caching. When requirements specify caching images, video, or web assets at global edge locations to offload origin servers, CloudFront is the definitive choice. Global Accelerator NEVER caches.
  • 2
    Giao thức TCP/UDP không phải HTTP hoặc cần 2 IP tĩnh → CHỌN GLOBAL ACCELERATOR Non-HTTP TCP/UDP or 2 Static Anycast IPs → CHOOSE GLOBAL ACCELERATOR Bất kỳ khi nào đề bài nhắc đến máy chủ game (UDP), dịch vụ gọi thoại VoIP, hoặc khách hàng đòi hỏi đúng 2 địa chỉ IP tĩnh để mở cổng tường lửa, Global Accelerator luôn là câu trả lời duy nhất đúng. Whenever a scenario involves UDP gaming, VoIP audio, or corporate clients demanding 2 fixed static IPs for firewall whitelisting, Global Accelerator is the only valid answer.
  • 3
    Bảo vệ S3 Bucket phía sau CloudFront: Luôn dùng Origin Access Control (OAC) Protecting S3 behind CloudFront: Always use Origin Access Control (OAC) Tuyệt đối không để S3 Bucket ở trạng thái Public khi đã dùng CloudFront. Bật tính năng OAC và cấu hình Bucket Policy chỉ cho phép dịch vụ CloudFront truy cập. (OAC là phiên bản thay thế hiện đại của OAI). Never leave S3 buckets publicly readable when fronted by CloudFront. Activate OAC and restrict bucket policies to CloudFront service principals (OAC is the modern successor to legacy OAI).

    Chuyển thảm họa Multi-Region không phụ thuộc DNS TTL: Dùng Global Accelerator Multi-Region automated failover without DNS propagation delays: Use Global Accelerator Nếu dùng Route 53 DNS Failover, khách hàng vẫn có thể bị trỏ vào Region đã sập do các nhà mạng ISP lưu cache DNS (DNS TTL). Với AWS Global Accelerator, địa chỉ Anycast IP giữ nguyên không đổi, việc chuyển hướng sang Region thứ 2 diễn ra dưới 1 phút hoàn toàn ở tầng mạng nội bộ AWS! Route 53 DNS failover is subject to client/ISP DNS caching TTL delays. With AWS Global Accelerator, the Anycast IP never changes, executing automated traffic failover to healthy secondary regions in under 1 minute entirely within the AWS network fabric!
