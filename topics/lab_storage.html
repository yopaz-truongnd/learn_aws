2. Bài thực hành 1: Mount Amazon EFS lên 2 máy chủ EC2 đồng thời 2. Hands-On 1: Mounting Amazon EFS Across 2 EC2 Instances Simultaneously

Mã nguồn trong aws_document/efs/efs.sh Source code in aws_document/efs/efs.sh
# on both instances: sudo yum install -y amazon-efs-utils sudo mkdir /efs sudo mount -t efs fs-yourid:/ /efs # you can now write files into /efs and they'll be available on both your ec2 instances! # Ví dụ kiểm tra đồng bộ tức thì: echo "Hello from Instance 1" | sudo tee /efs/hello.txt cat /efs/hello.txt
Giải thích từng lệnh & Các bước thực hiện Command Breakdown & Step-by-Step Guide
  • 1
    Chuẩn bị Security Group cho EFS và EC2 (Rất hay quên!) Configure Security Groups for EFS and EC2 (Critical Step!) Tạo EFS-SG gắn cho EFS Mount Targets và mở Inbound Rule: giao thức NFS (TCP Port 2049) với Source là Security Group của EC2 (EC2-SG). Nếu quên mở cổng 2049, lệnh mount sẽ bị treo vô hạn và báo lỗi Connection timed out. Create an EFS-SG for your EFS Mount Targets and add an Inbound Rule allowing NFS (TCP Port 2049) from your EC2 Security Group (EC2-SG). Without port 2049 open, the mount command hangs and times out.
  • 2
    Cài đặt công cụ hỗ trợ: sudo yum install -y amazon-efs-utils Install EFS Mount Helper: sudo yum install -y amazon-efs-utils Gói amazon-efs-utils cung cấp trình mount helper cho kiểu -t efs, tự động phân giải DNS của File System ID sang địa chỉ IP của Mount Target nằm trong cùng AZ với máy chủ EC2 và hỗ trợ mã hóa đường truyền TLS. The amazon-efs-utils package provides the -t efs mount helper, automatically resolving the File System ID DNS to the local AZ's Mount Target IP and supporting in-transit TLS encryption.
  • 3
    Tạo thư mục đích và Mount: sudo mkdir /efs && sudo mount -t efs fs-yourid:/ /efs Create Mount Point & Mount: sudo mkdir /efs && sudo mount -t efs fs-yourid:/ /efs Thay fs-yourid bằng File system ID thực tế trên EFS Console (ví dụ fs-0a1b2c3d4e5f6g7h8). Nếu muốn mã hóa dữ liệu trên đường truyền (In-transit encryption), thêm cờ -o tls vào lệnh mount. Replace fs-yourid with your actual EFS File system ID (e.g., fs-0a1b2c3d4e5f6g7h8). To enforce in-transit encryption, add the -o tls option to the mount command.
  • 4
    Kiểm chứng chia sẻ dữ liệu thời gian thực giữa 2 máy chủ Verify Real-Time File Sharing Across Both Instances Trên EC2 thứ nhất, tạo tệp /efs/hello.txt. Ngay lập tức chuyển sang cửa sổ terminal của EC2 thứ hai và chạy ls -l /efs → tệp tin xuất hiện tức thì trên cả 2 máy chủ! On Instance 1, write to /efs/hello.txt. Immediately switch to Instance 2's terminal and run ls -l /efs → the file is instantaneously visible on both instances!

# Tài liệu gốc trong aws_document/ebs/commands.txt: # See: https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ebs-using-volumes.html # See: https://www.unixmen.com/how-to-measure-disk-performance-with-fio-and-ioping/ # 1. Liệt kê các ổ đĩa khối (Block devices) đã gắn vào EC2: lsblk # 2. Kiểm tra ổ đĩa mới (ví dụ /dev/xvdf hoặc /dev/nvme1n1) đã có filesystem chưa: sudo file -s /dev/xvdf # Nếu trả về "/dev/xvdf: data" nghĩa là ổ đĩa trống # 3. Định dạng (Format) ổ đĩa mới sang chuẩn XFS và mount vào thư mục /data: sudo mkfs -t xfs /dev/xvdf sudo mkdir /data sudo mount /dev/xvdf /data # 4. Đo độ trễ đĩa (Latency) bằng ioping và đo IOPS bằng fio: sudo yum install -y fio ioping ioping -c 10 /data sudo fio --randrepeat=1 --ioengine=libaio --direct=1 --gtod_reduce=1 --name=test --filename=/data/test --bs=4k --iodepth=64 --size=1G --readwrite=randrw --rwmixread=75
Lưu ý khi Format ổ đĩa từ Snapshot
Chỉ chạy lệnh mkfs -t xfs đối với ổ đĩa EBS mới tinh (trống). Nếu bạn tạo EBS Volume từ một Snapshot có sẵn dữ liệu, tuyệt đối KHÔNG chạy mkfs vì nó sẽ xóa sạch toàn bộ dữ liệu trong Snapshot!
Only run mkfs -t xfs on a brand-new empty EBS volume. If you restored the volume from an existing Snapshot, NEVER run mkfs as it will wipe the restored filesystem!
Tự động Mount khi khởi động lại (/etc/fstab)
Lệnh mount thông thường sẽ mất hiệu lực khi Reboot máy. Để tự động gắn ổ đĩa EBS hoặc EFS mỗi khi khởi động, hãy thêm cấu hình UUID của ổ đĩa vào tệp /etc/fstab kèm tham số nofail.
Manual mount commands do not persist across reboots. To auto-mount EBS or EFS volumes at boot, add an entry using the volume's UUID to /etc/fstab with the nofail option.
