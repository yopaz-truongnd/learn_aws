2. Bài thực hành 1: Mã hóa & Giải mã tệp bí mật với AWS KMS CLI 2. Hands-On 1: Encrypting & Decrypting Secret Files with AWS KMS CLI
Tệp nguồn: aws_document/kms/ExampleSecretFile.txt & aws_document/kms/kms-demo-cli.sh Source files: aws_document/kms/ExampleSecretFile.txt & aws_document/kms/kms-demo-cli.sh
Mã nguồn trong aws_document/kms/kms-demo-cli.sh (Nội dung ExampleSecretFile.txt: "SuperSecretPassword") Source code in aws_document/kms/kms-demo-cli.sh (ExampleSecretFile.txt contains: "SuperSecretPassword")
# 1) MÃ HÓA (ENCRYPTION) aws kms encrypt --key-id alias/tutorial \ --plaintext fileb://ExampleSecretFile.txt \ --output text --query CiphertextBlob \ --region eu-west-2 > ExampleSecretFileEncrypted.base64 # Giải mã Base64 ra file nhị phân (Linux / macOS): cat ExampleSecretFileEncrypted.base64 | base64 --decode > ExampleSecretFileEncrypted # Giải mã Base64 trên Windows CMD / PowerShell: certutil -decode .\ExampleSecretFileEncrypted.base64 .\ExampleSecretFileEncrypted # 2) GIẢI MÃ (DECRYPTION) — Chú ý: KHÔNG cần truyền --key-id! aws kms decrypt --ciphertext-blob fileb://ExampleSecretFileEncrypted \ --output text --query Plaintext \ --region eu-west-2 > ExampleFileDecrypted.base64 # Giải mã Base64 về lại văn bản gốc (Linux / macOS): cat ExampleFileDecrypted.base64 | base64 --decode > ExampleFileDecrypted.txt # Giải mã Base64 trên Windows: certutil -decode .\ExampleFileDecrypted.base64 .\ExampleFileDecrypted.txt
Tại sao lệnh kms decrypt KHÔNG cần truyền --key-id?
Khi KMS mã hóa dữ liệu bằng aws kms encrypt, siêu dữ liệu về ARN của khóa KMS (CMK) đã được nhúng trực tiếp bên trong phần header của gói CiphertextBlob. Do đó khi gọi aws kms decrypt, KMS tự động biết phải dùng khóa nào để giải mã!
When KMS encrypts data via aws kms encrypt, the KMS Key ARN metadata is embedded directly inside the CiphertextBlob header. Therefore, aws kms decrypt automatically identifies which KMS key to use without needing --key-id!
Giới hạn 4 KB của KMS API & Envelope Encryption
API kms:Encrypt chỉ nhận trực tiếp tối đa 4 KB (4096 bytes) dữ liệu. Nếu cần mã hóa file lớn hơn 4 KB, bạn bắt buộc phải dùng cơ chế Envelope Encryption: gọi API aws kms generate-data-key để lấy Data Key mã hóa file tại máy cục bộ.
The kms:Encrypt API accepts a maximum payload of 4 KB (4096 bytes). To encrypt files larger than 4 KB, you MUST use Envelope Encryption via aws kms generate-data-key.

3. Bài thực hành 2: Quản lý cấu hình & mật khẩu với SSM Parameter Store (CLI & Lambda) 3. Hands-On 2: Managing Configs & Secrets with SSM Parameter Store (CLI & Lambda)
Tệp nguồn: aws_document/ssm/cli.sh & aws_document/ssm/handler.py Source files: aws_document/ssm/cli.sh & aws_document/ssm/handler.py
aws_document/ssm/cli.sh (Truy vấn qua AWS CLI)
# 1. Lấy tham số theo tên (Chưa giải mã SecureString): aws ssm get-parameters --names /my-app/dev/db-url /my-app/dev/db-password # 2. Lấy tham số KÈM giải mã KMS (--with-decryption): aws ssm get-parameters --names /my-app/dev/db-url /my-app/dev/db-password --with-decryption # 3. Lấy toàn bộ tham số theo nhánh thư mục (/my-app/dev/): aws ssm get-parameters-by-path --path /my-app/dev/ # 4. Đệ quy toàn bộ cây (/my-app/) kèm giải mã: aws ssm get-parameters-by-path --path /my-app/ --recursive --with-decryption
aws_document/ssm/handler.py (Đọc từ AWS Lambda bằng Boto3)
import json import boto3 import os ssm = boto3.client('ssm', region_name="eu-west-3") dev_or_prod = os.environ['DEV_OR_PROD'] def lambda_handler(event, context): db_url = ssm.get_parameters( Names=["/my-app/" + dev_or_prod + "/db-url"] ) print(db_url) db_password = ssm.get_parameters( Names=["/my-app/" + dev_or_prod + "/db-password"], WithDecryption=True ) print(db_password) return "worked!"
Các bước thực hành & Phân quyền IAM cho Lambda Step-by-Step Guide & Lambda IAM Permissions
  • 1
    Tạo cây tham số phân cấp trên Systems Manager → Parameter Store Create Hierarchical Parameters in Systems Manager → Parameter Store Tạo 4 tham số: /my-app/dev/db-url, /my-app/prod/db-url (kiểu String) và /my-app/dev/db-password, /my-app/prod/db-password (kiểu SecureString mã hóa bằng KMS). Việc đặt tên theo dạng đường dẫn /app/env/key giúp gom nhóm và phân quyền IAM theo từng môi trường cực kỳ gọn gàng! Create 4 parameters: /my-app/dev/db-url, /my-app/prod/db-url (type String) and /my-app/dev/db-password, /my-app/prod/db-password (type SecureString encrypted with KMS). Using path hierarchies like /app/env/key simplifies bulk retrieval and scoped IAM policies!
  • 2
    Cấp quyền IAM Execution Role cho hàm Lambda (Bẫy thực hành!) Grant IAM Execution Role Permissions to Lambda (Common Pitfall!) Để handler.py chạy thành công khi có WithDecryption=True, IAM Role của hàm Lambda bắt buộc phải có:
    • Quyền ssm:GetParameters (hoặc AmazonSSMReadOnlyAccess).
    • Nếu SecureString dùng Customer Managed KMS Key (CMK) riêng, IAM Role của Lambda phải có thêm quyền kms:Decrypt trên khóa CMK đó!     For handler.py to succeed with WithDecryption=True, the Lambda Execution Role requires:
    • ssm:GetParameters permission (or AmazonSSMReadOnlyAccess).
    • If the SecureString uses a Customer Managed KMS Key (CMK), the role ALSO needs kms:Decrypt permission on that CMK!
  • 3
    Cấu hình biến môi trường DEV_OR_PROD trên Lambda Set the DEV_OR_PROD Environment Variable in Lambda Trong tab Configuration → Environment variables của Lambda, thêm key DEV_OR_PROD với giá trị dev (hoặc prod). Nhờ vậy bạn dùng chung 1 mã nguồn handler.py cho mọi môi trường mà không cần sửa code! Under Lambda's Configuration → Environment variables, add key DEV_OR_PROD with value dev (or prod). This lets the exact same handler.py code dynamically switch environments without code changes!
