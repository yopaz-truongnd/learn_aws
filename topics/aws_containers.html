🔴 6 Bẫy đề thi cốt lõi về Container 🔴 6 Core Container Exam Traps • Task Role vs Task Execution Role (Bẫy số 1):
  - Task Execution Role: Dành cho ECS Agent (kéo ảnh từ ECR, ghi log sang CloudWatch, lấy mật khẩu từ Secrets Manager).
  - Task Role: Dành cho chính mã ứng dụng bên trong container (gọi S3, DynamoDB, SQS).
• Serverless Containers = AWS Fargate: Không cần quản lý máy chủ EC2, không vá lỗi OS, chỉ cần chỉ định vCPU và RAM, trả tiền theo giây.
• Dynamic Port Mapping = ALB: Khi chạy nhiều bản sao container trên cùng 1 máy chủ EC2, đặt hostPort: 0 và kết nối qua Application Load Balancer.
• Lưu trữ dùng chung đa AZ cho Containers = Amazon EFS: Cả ECS EC2 và Fargate đều hỗ trợ mount trực tiếp EFS volume để chia sẻ dữ liệu đọc/ghi đồng thời.
• EKS vs ECS: Chọn Amazon EKS khi doanh nghiệp đã có sẵn hệ sinh thái Kubernetes on-premise hoặc muốn di chuyển đa đám mây (Cloud-agnostic). Chọn ECS khi muốn tích hợp sâu và đơn giản với AWS.
• AWS App Runner: Dành cho ứng dụng web container đơn giản, hoàn toàn không cần kiến thức về cấu hình cụm ECS/EKS hay VPC phức tạp. • Task Role vs Task Execution Role (#1 Trap):
  - Task Execution Role: For the ECS Agent itself (pulling image from ECR, sending logs to CloudWatch, fetching secrets from Secrets Manager).
  - Task Role: For application code running inside the container (calling S3, DynamoDB, SQS).
• Serverless Containers = AWS Fargate: Zero EC2 provisioning, zero OS patching; simply specify vCPU/RAM and pay per second.
• Dynamic Port Mapping = ALB: Running multiple container replicas on a single EC2 host requires hostPort: 0 mapped via Application Load Balancer.
• Multi-AZ Shared Storage for Containers = Amazon EFS: Both ECS EC2 and Fargate natively mount EFS volumes for shared multi-AZ read/write persistence.
• EKS vs ECS: Choose Amazon EKS when migrating existing Kubernetes workloads or requiring cloud-agnostic portability. Choose ECS for simplicity and native AWS integration.
• AWS App Runner: Simplest container web runner requiring zero ECS/EKS cluster or VPC orchestration knowledge.

💻 1. ECS (EC2 Launch Type) 💻 1. ECS (EC2 Launch Type)
Là gì? (Definition) What is it?

Mô hình chạy container ECS trên một cụm máy chủ Amazon EC2 do khách hàng tự quản lý (tự chọn AMI, loại máy chủ, cấu hình ổ đĩa EBS và mạng VPC).

Running ECS containers on a cluster of Amazon EC2 instances managed by the user (custom AMIs, instance types, EBS volumes, and VPC network configuration).

Dùng khi nào? (When to use) When to use?

Khi cần tối ưu chi phí tối đa bằng cách tận dụng EC2 Reserved Instances / Savings Plans hoặc Spot Instances, cần can thiệp quyền root hệ điều hành máy chủ chủ, hoặc cần loại instance đặc thù (GPU, ARM Graviton).

When optimizing costs with Reserved Instances / Savings Plans or Spot Instances, requiring host OS root access, or needing specialized hardware instances (GPU, ARM Graviton).

Khác gì? (Key Differences) Key Differences

Bạn phải tự cấu hình Auto Scaling cho cụm EC2 (ECS Capacity Providers) và chịu trách nhiệm bảo trì, vá lỗi hệ điều hành. Trả tiền cho toàn bộ máy chủ EC2 kể cả khi container không chạy hết dung lượng.

Requires managing underlying EC2 Auto Scaling (Capacity Providers) and OS patching. Billed for the provisioned EC2 instances regardless of actual container utilization.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: Muốn chạy nhiều container map cùng port trên 1 EC2 → Phải dùng Dynamic Port Mapping kết hợp với Application Load Balancer (ALB). Không được dùng Classic Load Balancer!

⚠️ Exam Trap: Running multiple containers on the same port on a single host requires Dynamic Port Mapping paired with Application Load Balancer (ALB). CLB is unsupported!

⚡ 2. AWS Fargate (Serverless) ⚡ 2. AWS Fargate (Serverless)
Là gì? (Definition) What is it?

Mô hình tính toán không máy chủ (Serverless Compute Engine) cho cả Amazon ECS và Amazon EKS. AWS hoàn toàn quản lý hạ tầng phần cứng và hệ điều hành ảo hóa phía dưới.

Serverless compute engine for both Amazon ECS and Amazon EKS. AWS entirely manages underlying hardware provisioning, orchestration, and host virtualization.

Dùng khi nào? (When to use) When to use?

Khi doanh nghiệp muốn tập trung 100% vào phát triển ứng dụng container mà không muốn tốn công sức vận hành, vá lỗi OS hay căn chỉnh dung lượng máy chủ (No Infrastructure Management).

When businesses want zero infrastructure management overhead—focusing entirely on containerized code without patching OS or capacity-planning server fleets.

Khác gì? (Key Differences) Key Differences

Mỗi Fargate Task chạy trong môi trường vi ảo hóa (microVM) độc lập với ENI riêng trong VPC. Thanh toán chính xác theo số vCPU và GB bộ nhớ RAM tiêu thụ trong thời gian task chạy.

Each Fargate Task runs in its own isolated microVM with a dedicated VPC ENI. Billed strictly for vCPU and memory resources consumed per second of task lifetime.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: Fargate không hỗ trợ EC2 Instance Store! Nếu container cần lưu trữ dữ liệu bền vững dùng chung giữa nhiều tasks ở các AZ khác nhau → Phải cấu hình Amazon EFS Volume.

⚠️ Exam Trap: Fargate does not support Instance Store! For cross-AZ persistent shared storage across multiple tasks → Must configure an Amazon EFS Volume.

☸️ 3. Amazon EKS ☸️ 3. Amazon EKS
Là gì? (Definition) What is it?

Dịch vụ quản lý Kubernetes tiêu chuẩn nguồn mở trên đám mây AWS. AWS quản lý tính sẵn sàng cao của cụm điều khiển Kubernetes Control Plane trên đa AZ.

Managed standard open-source Kubernetes service on AWS. AWS automatically manages multi-AZ high availability and scaling of the Kubernetes Control Plane.

Dùng khi nào? (When to use) When to use?

Khi doanh nghiệp đang vận hành cụm Kubernetes on-premise cần chuyển lên AWS giữ nguyên các file cấu hình YAML (Pods, Deployments, Services, Helm charts) hoặc yêu cầu khả năng di chuyển đa đám mây.

Migrating existing on-premises Kubernetes workloads to AWS maintaining standard YAML manifests (Pods, Deployments, Services, Helm charts) or ensuring multi-cloud portability.

Khác gì? (Key Differences) Key Differences

EKS tính phí cố định $0.10/giờ cho mỗi cụm Control Plane + chi phí tài nguyên Worker Nodes (EC2 hoặc Fargate). Phức tạp hơn ECS nhưng tương thích 100% với hệ sinh thái Kubernetes toàn cầu.

EKS charges a fixed $0.10/hr per cluster Control Plane plus compute worker nodes. Steeper learning curve than ECS but 100% compatible with the broader Kubernetes ecosystem.

Bẫy thi & Từ khóa (Traps & Keywords) Traps & Keywords

⚠️ Bẫy đề thi: Đề bài nhắc đến "Kubernetes", "kubectl", "Pod", "Helm" → Chọn ngay Amazon EKS. Nếu đề bài chỉ nói "Docker container đơn giản, ít công quản lý nhất" → Chọn Amazon ECS với Fargate.

⚠️ Exam Trap: Scenarios citing "Kubernetes", "kubectl", "Pods", or "Helm" → Instantly select Amazon EKS. Scenarios wanting "simplest Docker containers with minimal operational effort" → Select ECS with Fargate.

2. Bẫy đề thi số 1: Phân biệt ECS Task Role vs ECS Task Execution Role 2. #1 Exam Trap: ECS Task Role vs ECS Task Execution Role
Hiểu đúng bản chất của 2 IAM Role trong ECS Task Definition để không mất điểm oan Accurately distinguishing the 2 IAM Roles in ECS Task Definitions
🤖 1. ECS Task Execution Role (Dành cho ECS Infrastructure Agent) 🤖 1. ECS Task Execution Role (For ECS Agent Infrastructure)

• Bản chất: Role này được cấp cho chính ECS Container Agent (tiến trình nền của AWS) để nó có thể thay mặt bạn chuẩn bị và khởi chạy container.
• Các quyền cấp trong role:
  1. Kéo Docker image từ kho lưu trữ riêng tư Amazon ECR (ecr:GetAuthorizationToken, ecr:BatchGetImage).
  2. Gửi nhật ký container lên Amazon CloudWatch Logs (logs:CreateLogStream, logs:PutLogEvents).
  3. Lấy chuỗi kết nối cơ sở dữ liệu và mật khẩu từ AWS Secrets Manager hoặc SSM Parameter Store đưa vào biến môi trường.

• Essence: Assumed by the ECS Container Agent itself to provision, launch, and bootstrap container tasks on your behalf.
• Permissions granted:
  1. Pulling private container images from Amazon ECR.
  2. Streaming container logs to Amazon CloudWatch Logs.
  3. Injecting database credentials from AWS Secrets Manager or SSM Parameter Store into container environment variables.

📦 2. ECS Task Role (Dành cho mã nguồn ứng dụng chạy bên trong) 📦 2. ECS Task Role (For Application Code Inside Container)

• Bản chất: Role này được cấp cho chính ứng dụng đang chạy bên trong container.
• Các quyền cấp trong role:
  1. Gửi và nhận tin nhắn từ hàng đợi Amazon SQS.
  2. Đọc ghi tài liệu trong cơ sở dữ liệu Amazon DynamoDB.
  3. Upload hoặc download tệp từ Amazon S3 buckets.
👉 Nguyên tắc vàng: Nhờ có Task Role, bạn không bao giờ được hard-code Access Keys (AK/SK) vào file cấu hình hay mã nguồn container.

• Essence: Assumed directly by the application code running inside the container.
• Permissions granted:
  1. Polling and processing messages from Amazon SQS.
  2. Reading/writing items to Amazon DynamoDB.
  3. Uploading and downloading objects in Amazon S3 buckets.
👉 Golden Rule: Eliminates the need to ever hardcode AWS API credentials inside container images.

4. Kiến trúc lưu trữ bền vững cho Containers: EBS vs Amazon EFS 4. Persistent Storage Architecture for Containers: EBS vs Amazon EFS
Giải quyết bài toán lưu trữ tệp tin khi container bị hủy hoặc di chuyển sang AZ khác Handling stateful container persistence across task recreation and cross-AZ failover
📁 Amazon EFS (Giải pháp chia sẻ tệp đa AZ cho Containers) 📁 Amazon EFS (Multi-AZ Shared File Storage for Containers)

• Đặc điểm: Hệ thống tệp POSIX dùng chung hoạt động ở cấp độ Multi-AZ.
• Khả năng gắn kết: Cho phép hàng trăm Container Tasks chạy trên cả Fargate và EC2 cùng đọc/ghi đồng thời vào một tệp dữ liệu.
• Tình huống đề thi: Một ứng dụng WordPress hoặc hệ thống CMS chạy trên ECS Fargate với nhiều bản sao (replicas) phân bổ trên 2 Availability Zones cần truy cập chung một thư mục uploads → Bắt buộc chọn Amazon EFS.

• Profile: Multi-AZ POSIX network file system.
• Attachment concurrency: Allows hundreds of container tasks across both Fargate and EC2 to read/write concurrently.
• Exam Scenario: A stateful WordPress or CMS deployment on ECS Fargate running across multiple AZs requiring shared media assets → Must choose Amazon EFS.

💽 Amazon EBS (Lưu trữ khối gắn theo từng Task) 💽 Amazon EBS (Block Storage Attached per Task)

• Đặc điểm: Khối đĩa hiệu năng cao nhưng bị khóa trong 1 Availability Zone (AZ-locked).
• Khả năng gắn kết: ECS hỗ trợ tự động tạo và gắn một ổ đĩa EBS chuyên dụng cho từng Task độc lập.
• Giới hạn: Không thể chia sẻ ổ đĩa EBS giữa nhiều tasks ở các AZ khác nhau. Nếu task bị chuyển sang máy chủ ở AZ khác → Ổ EBS cũ không thể gắn trực tiếp sang AZ mới.

• Profile: High-performance block storage, strictly AZ-locked.
• Attachment concurrency: ECS manages dedicated volume provisioning per individual task instance.
• Limitations: Cannot share a single volume across tasks in separate AZs. If a task reschedules to a new AZ, the EBS volume cannot follow.

2
Cần phân quyền cho code bên trong container = ECS Task Role Granting Permissions to Application Code = ECS Task Role
Không cấp quyền AWS cho EC2 Instance Profile của máy chủ host! Luôn cấp quyền tối thiểu bằng ECS Task Role được định nghĩa trực tiếp trong Task Definition để từng container chỉ có đúng quyền cần thiết.
Never assign broad AWS permissions to the host EC2 Instance Profile! Always grant least-privilege permissions through the ECS Task Role defined in the Task Definition.
3
Chia sẻ dữ liệu bền vững giữa các Container = Amazon EFS Persistent Shared Data Between Containers = Amazon EFS
Ổ đĩa của container là tạm thời (ephemeral). Nếu nhiều container cần đọc/ghi dữ liệu dùng chung trên nhiều Availability Zones → Luôn gắn Amazon EFS Volume vào Task Definition.
Container local storage is ephemeral. When multi-container replicas require cross-AZ shared persistent read/write access → Mount an Amazon EFS Volume.
4
Tương thích Kubernetes / Helm = Amazon EKS Kubernetes Ecosystem & Tooling = Amazon EKS
Nếu bài thi có các từ khóa đặc trưng của hệ sinh thái Kubernetes: "k8s", "kubectl", "Pod", "Helm Charts", "CRDs" hoặc "tương thích đa đám mây" → Chọn ngay Amazon EKS.
If scenario mentions distinctive Kubernetes terminology: "k8s", "kubectl", "Pod", "Helm Charts", "CRDs", or "multi-cloud portability" → Always choose Amazon EKS.
